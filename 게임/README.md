# Grid Defenders — 실행과 검증

기준일 2026-11-08 / WEB-185. PixiJS 8.22.0, TypeScript 7.0.2, Vite 8.3.5 기반 웹 시제품이다. 최신 상태는 [현재 구현 현황](../문서/05_프로젝트정의/현재구현현황.md)을 따른다. [종합 보고서](../문서/06_프로젝트종합보고/2026-11-07/프로젝트종합보고서.md)는 WEB-179 사업·통합 결과를 보존한 스냅샷이다.

## 실행

게임 폴더에서 실행한다. 처음 설치하거나 잠금 파일이 바뀌었을 때 npm ci로 의존성을 설치한다.

```sh
npm ci
npm run dev
```

Vite가 출력하는 로컬 주소를 연다. 기본 로비는 index.html, 실제 가로 전투는 battle-landscape.html?battle=normal&from=camp이다. battle=infinite-test는 패배·시간 제한을 완화한 개발 모드다. lobby-preview.html, battle-landscape-preview.html은 별도 시안 진입점이다.

## 검증·빌드

```sh
npm test
npm run build
npm run preview
```

- npm test: 소스·테스트 타입 검사와 Vite SSR 기반 세로·가로 모델 검사. 새 .check.ts 파일은 실행기 분류에 등록한다.
- 모델 검사는 30개 파일을 화면 조건별로 실행한다. WEB-185 기준 59회·1,539항목을 통과했다. 세로 전용 1건은 가로에서 대상 아님으로 출력한다. DOM·캔버스·WebGL이 필요한 15개 파일은 별도 브라우저 검사가 필요하며 이 명령에서 실행하지 않는다.
- npm run build: 소스 타입 검사와 4개 진입점 프로덕션 빌드. dist는 재생성 산출물이다.
- 모델 통과는 실제 렌더링·터치·기기 저장 복귀 성공을 뜻하지 않는다.

브라우저11개 검사는 Vite의 /tests/browser-check.html 전용 페이지에서 [재실행 JS](../문서/06_프로젝트종합보고/2026-11-07/브라우저검증_재실행.js)를 실행한다. 검사는 해당 페이지의 DOM을 교체하므로 실제 게임 탭에서 실행하지 않는다. 결과는 window.audit에 기록한다.4개 육안 연출 갤러리는 별도다.

## 7×6 보스 진형

웨이브 화면 오른쪽 진형 버튼을 누르면 현재 소환된 유닛의 진형을 편집한다. 가로 7칸·세로 6칸이며 위쪽 진행 방향 기준으로 전열·중열·후열 각각 두 행이다. 하단 상점 카드 줄의 자동배치는 보병을 전열, 궁병·마법병을 후열, 모든 영웅을 중열에 우선 배분한다. 전열이나 후열이 가득 차면 병사를 빈칸에 배분하며 영웅은 중열을 유지한다.

WEB-181에서 진형창을 전장 오른쪽 빈 공간으로 옮겼다. 800×360 전장 기준 x524/y44·272×312px이며 전장과 8px, 오른쪽 끝과 4px 간격을 둔다. WEB-182에서 전열·후열에 한 줄씩 추가해42칸으로 늘리고 패널 제목을 제거했다. 칸은30×42px다. 완료72×72px와 자동배치88×72px를 배치판 바로 아래x160/y260부터 배치한다(WEB-183). 배경 암막은 투명하게 바꾸되 기존 native modal의 편집 중 입력 차단·ESC·바깥 클릭·포커스 복귀를 유지한다. [현재 패널 정의](../문서/03_작업기록/WEB-182_진형6행과하단조작/4_정의문서.md)

유닛 칸을 선택한 뒤 다른 칸을 누르면 이동하거나 교환한다. 영웅을 중열 밖으로 옮기는 이동·교환은 허용하지 않는다. 편집 중 전투는 정지하고 닫으면 편집 전 재생/정지 상태로 돌아간다. 변경은 현재 전투 체크포인트에 저장된다. 새 저장은 formationRows=6을 기록하고 기존7×4 진형은 각 칸을 한 행 아래로 옮겨 같은 구역에 보존한다. 진형이 없는 구 저장은 역할별 기본 배치를 보충한다. 새 전투에서는 진형을 초기화한다.

편집판의 위쪽 방향을 시계 방향 90도로 회전해 다음 가로 보스전의 오른쪽 진행 방향에 적용한다. 웨이브 배치칸·재화·능력치는 그대로다. [WEB-180 정의](../문서/03_작업기록/WEB-180_7x4진형과자동배치/4_정의문서.md)

## 직사각형 길목 (WEB-185)

가로 길목은 직각 네 변이다. 진행 중심x131/479/y68/264, 둘레1,088, 세로 길 기준 폭58px이며 배치20칸·58×42px를 유지한다. 기존 필드의 흙 구역을 재사용해 코너를 채우고 잔디 경계를 부드럽게 연결했다. 이전 곡선 길 저장도 몬스터의 진행 거리와 체력을 보존하며 현재 경로 좌표로 복원한다. 브라우저15항목·모델1,539항목·최종 빌드를 통과했다. [기록](../문서/03_작업기록/WEB-185_직사각형길목/3_작업일지.md).

## 거리 허수아비·원거리 영웅 표시 (WEB-183)

개발자 도구의 거리 허수아비 ON/OFF로 선택과 무관하게 원을 표시한다.1R=130,0.5R 간격으로 최대3R(390)까지 파랑·노랑을 번갈아 표시한다. 허수아비는 드래그·방향키로 움직이며 웨이브와 보스에서 같은 전투 좌표 거리를 사용한다. 큰 원은 전장 경계에서 잘린다.

금발 전사의 원래 몸 높이57/72를 기준으로, 첨부된 지팡이 영웅(원거리 딜러/ranged)을 같은 높이로 확대했다. 투명 여백과 지팡이를 제외한 머리~발 기준이며 발 위치와 비율을 유지한다. 거리 UI26항목·영웅 아트165항목·빌드·검사 타입 확인을 통과했다. [검증 기록](../문서/03_작업기록/WEB-183_거리허수아비와영웅키맞춤/3_작업일지.md).

## 아트 재생성

외부 작업 폴더 없이 [보관 원본](../자료/아트원본/README.md)으로 슬라임·금발 전사 아틀라스를 재생성할 수 있다. scripts/pack-slime-art.ps1, scripts/pack-blond-art.ps1의 기본 입력은 자료/아트원본이다. 검토할 때 -OutputRoot를 별도 폴더로 지정하면 배포 이미지를 덮어쓰지 않고 비교할 수 있다. 원래 위치와 SHA-256은 manifest에 남긴다.

## 현재 한계

로비 영웅과 전투 명단 통합, 강제 튜토리얼, 40웨이브 최종 콘텐츠, 계정·결제는 완료되지 않았다. WEB-180 진형 기능은 800×360 브라우저에서 32개 UI 항목을 검증했다. WEB-181 우측 배치는 빌드와 브라우저 23항목을 통과했으며 800×360 화면 및 폭1200에서 가운데 정렬된 전장을 확인했다. [진형 검증](../문서/03_작업기록/WEB-182_진형6행과하단조작/검증/formation-six-result.json). 실제 모바일 기기 조작은 후속 검증이다. 수치·경제·보상은 임시이며 출시 밸런스가 아니다. 브라우저 저장은 기기·브라우저 단위이며 계정 동기화가 없다. 개발 도구는 현재 화면에 노출되어 있다.
