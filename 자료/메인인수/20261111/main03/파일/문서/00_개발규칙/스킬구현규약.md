# 스킬 구현 규약 v1

2026-11-04 / WEB-091. 사용자 요청으로 정한 이후 스킬·평타·타격 이펙트 구현의 공통 기준. 새 승인 단계가 아니며, 최신 사용자 지시가 우선한다. 기존 스킬의 피해 수치를 일괄 변경하지 않는다.

## 1. 시작 전에 기록할 계약

| 항목 | 기록할 내용 |
|---|---|
| 식별 | 영웅, 평타/스킬, 웨이브/보스 적용 여부, 아이콘 원본 |
| 피해 | 각 타격 배율, 물리/마법, 총타수, 범위/단일/경로, 피해 판정 도형 |
| 대상 | 첫 대상 우선순위, 부족 시 반복 여부, 사망/사거리 이탈 시 재선정 규칙 |
| 시간 | 쿨타임, 시작 시점, 프레임 시간, 타격을 확정할 완료 프레임, 캔슬 규칙 |
| 좌표 | 시전자 발, 대상 중심, 대상 발밑 중 기준점, 추적/명중지점 고정 여부 |
| 원본 | 파일·해상도·행별 실제 셀 좌표·논리 번호와 이미지 번호 매핑 |
| 표시 | 캐릭터와 발광부 구분, 투명 여백, 화면 크기, 레이어, 최대 확장 범위 |
| 부가효과 | 수치·지속시간·중첩/갱신·피해와 적용 순서·아이콘 위치 |

↳ 쉽게 말하면: 언제 누구를 얼마나 때리는지와 어디에 어떤 그림을 보여줄지를 따로 적는다. 모호한 수치를 그림에서 추측해 추가하지 않는다.

## 2. 원본 추출·투명화

- 셀 크기가 같다고 가정하지 않는다. 각 행과 공통 효과의 경계를 실제 이미지로 측정하고 번호 누락을 명시한다. 제목·테두리·숫자·옆 그림이 섞이면 불합격이다.
- 프레임을 늘려 옆 그림을 포함시키지 않는다. 원본에 이미 잘린 부분은 빈 여백만으로 복원되지 않는다. 재추출, 원본 교체 또는 승인된 보완 방식으로 처리하고 한계를 기록한다.
- 캐릭터의 피부·의상 암부와 발광부를 구분한다. 빛 주변의 검정/네이비/어두운 색 배경은 투명하게 처리하고, 남은 RGB의 검은 테두리도 제거한다. 캐릭터 전체에 단순 밝기 필터를 적용하지 않는다.
- 원본의 `background`를 `transparent` 또는 `dark`로 명시한다. 이미 투명한 PNG에는 어두운 배경 제거를 다시 적용하지 않는다.
- 투명 PNG라도 여백을 확인한다. 현재 1536px 참조 시트 기준 각 프레임 사방24px의 안전 여백을 둔다. 다른 해상도는 비례 조정하고 프레임 끝의 alpha가0인지 검사한다.
- 잘림을 숨기려고 불투명 영역을 직선으로 강제 삭제하지 않는다. 부드러운 감쇠·잔광은 외곽에만 적용하며 중심의 밝은 타격점과 캐릭터를 보존한다.
- 원본 PNG는 보존한다. 가공은 공통 코드 또는 별도 출력물로 분리한다. 원본 출처와 변경 이력을 기록한다.

## 3. 좌표·크기·레이어

- 신규 시트는 `게임/src/skillVisual.ts`의 `SkillFrameSpec → createSkillFrame → SkillFrameArt` 계약을 사용한다. 캐릭터 발/타격 중심 등 pivot을 원본 좌표로 기록하고 패딩을 더한 anchor를 계산한다.
- `skillFramePlacement`는 원본 콘텐츠 크기로 배율을 계산한다. 패딩이 늘었다고 영웅이 작아져서는 안 되며 가로·세로 배율을 임의로 달리하지 않는다.
- 한 동작의 바닥 기준점은 고정한다. 점프가 이미 그려진 시트에 추가 점프 이동을 중복하지 않는다. 지면 분출은 대상 발밑, 피해 판정은 정해진 몸 중심에 둔다.
- 명중 위치 고정형은 충돌 시점 좌표를 저장한다. 몬스터가 이동한다고 남은 마법진/분출까지 따라가거나 프레임마다 흔들리면 안 된다.
- 배치칸은 선택·이동 기준이다. 칸 크기의 mask/overflow hidden으로 모션이나 이펙트를 자르지 않는다. 인접 칸·길목·상단 숲 여백으로 넘칠 수 있다. 전장 외부 UI까지 무제한 확장하는 것은 아니다.
- 타격 이펙트(평타 명중·찍기 분출)는 몬스터 본체보다 앞에 표시한다(WEB-092 사용자 수정). 지면 장식/시전자 잔광만 뒤쪽에 둘 수 있다. 이름·쿨타임·피해 숫자는 가능한 별도 상단 레이어에서 읽을 수 있게 유지하며, 인접 유닛을 지속해서 가리지 않는지 확인한다.
- 시각 범위와 피해 범위를 분리한다. 잔광을 넓혀도 사거리·대상 수·판정 도형은 변경하지 않는다.
- 웨이브(Pixi)와 보스(DOM/SVG)는 같은 프레임/기준점 데이터를 사용한다. SVG의 바깥 여백도 overflow visible로 유지한다. 시각 레이어는 입력을 가로채지 않는다.

## 4. 전투 시간·취소

- 프레임 번호는1부터, 피해는 지정 프레임이 **끝난 순간** 확정한다. 해당 프레임에 들어왔다고 미리 피해를 주지 않는다.
- 배속/정지는 공통 게임 시간으로 처리한다. 렌더 프레임이 빠져도 모든 완료 타격을 순서대로 한 번씩만 적용한다. 같은 프레임을 여러 번 그려도 피해를 재적용하지 않는다.
- 스킬은 평타 도중 사용할 수 있다. 이미 완료한 피해는 유지하고 미완료 평타 타격은 취소한다. 이미 발사된 투사체는 별도 취소 규칙이 없는 한 기존 동작을 유지한다.
- 쿨타임 값과 시작 시점을 전투 모델 하나에서 관리한다. 카드와 전장 바는 그 값을 읽기만 한다. 이미지 애니메이션 종료 콜백으로 쿨타임이나 피해를 결정하지 않는다.
- 타격 직전에 생존/사거리/캔슬 상태를 다시 확인한다. 부족 타수 보충은 영웅별 정의를 따른다. 암살자는 마지막 유효 적에게 남은 타수 집중, 유효 대상0명은 피해 없음.
- 웨이브 전환·새 게임·종료에서 잔여 모션과 이펙트를 정리한다. 피해/DPS/상태이상 중복 기록을 금지한다.

## 5. 완료 검사

1. 모든 논리 프레임을 밝은 초록/회색 배경에 나열해서 확인한다. 검은 미리보기만으로 완료하지 않는다. 사각 배경, 직선 잘림, 옆 프레임 조각, 번호/테두리, 신체 손실을 확인한다.
2. 실제 전장의 상단 길과 중앙에서 시전자 모션·대상 타격·옆 유닛을 함께 확인한다. 320px와390px 화면, 높은 DPI에서도 비율과 읽기 쉬운 정도를 확인한다.
3. 0.25×·1×·5× 및 일시정지에서 타격 시점·쿨타임·정지 상태를 확인한다. 저속에서는 타격 직전/완료/잔광을 각각 본다.
4. 관련 검사를 수행한다: 투명 외곽, 패딩 전후 기준점/배율, 프레임 매핑, 피해 횟수/배율, 적1·2·3명, 도중 사망/이탈, 캔슬, 배속·정지. 변경과 관련 없는 테스트를 기계적으로 추가하지 않는다.
5. 빌드·기능 검사와 시각 확인을 구분해 기록한다. 일부 검사만 수행했으면 그대로 기록한다. 구현 완료와 사용자의 최종 시각 확인은 별개다.

## WEB-091 적용 예

암살자 평타12·참격16·보스24·공통9 프레임. 참격 원본은12번이 없어11번을 한 프레임 유지. 공통5번 링은x510~646의 실제 범위를 사용한다. 순수 이펙트의 검은 배경 제거와24px 여백을 공통 처리하고, 캐릭터 보존 영역은 점프 프레임에 맞춰 지정한다. 원본에서 끊긴 잔광 경계는12px 감쇠와 약한4px 퍼짐으로 완화하며 원본의 없는 그림을 복원했다고 표현하지 않는다.

## 영웅 치명타 계약 — WEB-094
영웅 스킬은 사용이 성립한 순간 한 번만 치명타를 판정하고 공격력·critical 값을 시전 객체에 저장한다. 모든 후속 타격·범위 대상·경로 대상은 그 결과를 공유한다. 히트 처리나 대상 순회에서 재판정하지 않는다. 평타도 공격 동작 시작 시1회 판정하며 암살자 평타3연격과 투사체 범위 피해는 해당 동작의 결과를 공유한다. 초기 임시값은 영웅 공통10%/총 피해150%. 지휘자 공격 버프는 피해 스킬이 아니므로 판정하지 않는다.
