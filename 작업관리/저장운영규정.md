# 사용자 요청 시 저장 — v1.0 / 2026-11-09

사용자 직접 지시: “이제 자동저장하지말고 내가 저장하라할때만 하는걸로 하고 저장할때 작업기록 먼저 작성하고 올리는걸로 하자 지금 말나온김에 저장한번하고”.

메인01·02·03과 각 담당에 적용한다. 사용자 저장 요청 없이 Git 커밋·GitHub 업로드·예약 백업을 자동 수행하지 않는다. 제작/수정 요청이나 결과물 합격만으로 별도의 저장 요청을 받았다고 해석하지 않는다. 게임의 플레이 진행 저장 기능을 끄는 지시가 아니며, 이미지·코드 산출물 작성과 작업 착수·전달의 최소 근거 기록은 제작을 위해 유지한다.

저장 요청을 받으면 다음 순서로 수행한다.

1. 대상 작업·브랜치·파일·확인 시점·진행 중 여부를 조사한다. 기존 원본과 타 담당의 편집·스테이징을 보존한다.
2. 요청 원문, 수정 내용, 사전 판단, 작업일지, 현재 정의/완료·미완료, 검증 결과와 한계, 버전 관리 범위를 **커밋 전에** 작성한다. 기존 기록은 보존하고 이번 저장 차수를 추가한다. 제작 중인 항목을 완료·합격·실게임 통합으로 바꾸지 않는다.
3. 저장 대상과 제외 파일 목록을 확정하고 필요한 검증을 수행한다. 자격증명, 브라우저 프로필, node_modules, 캐시, 임시 잠금 등은 업로드하지 않는다. 크기 제한 등으로 올리지 못하는 파일은 로컬 원본을 보존하고 사유를 남긴다.
4. 검증된 게임 기준본과 작업 중 결과물 보관을 구분해 커밋·업로드한다. 필요하면 작업 공간의 HEAD·index·파일을 바꾸지 않는 별도 보관 브랜치를 사용한다. 원격 재작성/강제 푸시/미승인 병합은 하지 않는다.
5. 실제 GitHub 원격의 커밋 해시를 조회해 업로드 결과를 확인하고 저장 범위·보관 위치·남은 항목을 보고한다. 로컬 저장·로컬 커밋·원격 업로드를 구분한다.

이번 “저장한번” 요청은 현재 시점의 1회 저장 허가다. 이후 자동 반복 저장을 켜지 않는다. 다른 메인에서 별도 저장 요청을 받으면 공유 기록으로 동시 저장 충돌을 조정한다.

이 파일은 최신 사용자 직접 지시를 보존하는 원본이다. 기존 제작 필독/공통 규정의 해시를 작업 도중 바꾸어 활성 착수를 무효화하지 않도록 별도로 추가했다. 담당 메인은 이후 새 지시에도 이 저장 규칙을 전달한다.
