# Grid Defenders — 3개 메인과 세계관 도메인 작업 트리

현재 실제 담당 조직은 [조직 안내](조직안내.md)와 조직.json을 따른다. 아래 세계관 트리는 자료 분류이며 실제 AI 조직의 표시·부모 관계와는 구분한다. OPS-001/002의 인원·동일 계층 설명은 당시 기록이다.


공유 운영 원본: 이 `작업관리/` 폴더. 메인01은 현재 대화이며 메인02·03은 별도 브랜치·채팅이다. 모든 메인은 분석·기획·실제 시안 제작·선택 조합 제시·전문 지시·검수를 한다. 분야별 담당은 확인된 지시로 제작하고 기존 기준을 정교화한다.

## 실제 폴더 구성

```text
작업관리/
├─ README.md                  시작 안내
├─ 규정A.md                   공통 운영 기준
├─ 메인운영규정.md            시안·확인·전달·검수 절차
├─ 메인목록.json              메인3개의 경로·브랜치·채팅 기록
├─ 브랜치목록.json            UI와 기존7개 분야의 실제 위치
├─ 작업대장.md                공유 작업 목록 사용 안내
├─ 도메인/                    세계관→몬스터/캐릭터의 계층·원본 색인
├─ 기준/
│  ├─ world/                  세계관 원본·기획 연결

│  ├─ sprites/                캐릭터 동작·시트
│  ├─ characters/             캐릭터·세계관
│  ├─ items/                  아이템·밸런스
│  ├─ effects/                이펙트·제작 도구
│  ├─ splash/                 스플래시·일러스트

├─ 작업/<작업번호>/            task.json·차수별 확인·지시·영수증·결과
├─ 상태/                      동시 편집·브랜치 점유 기록
├─ 메인별자료/main01/          메인01 공유 자료의 시작 위치
├─ 도구/                      작업대장·사용법·절차 검사·준비 백업
└─ 기록/OPS-001/              준비 전 상태·복제·연결·초기화·검증 증거
```

실제 체크아웃과 역할:

| 역할 | Git 브랜치 | 위치 |
|---|---|---|
| 메인01·현재 대화 | main | C:/Users/user/Desktop/Grid Defenders |
| 메인02 | coord/main-02 | C:/Users/user/orca/workspaces/Grid Defenders/메인02 |
| 메인03 | coord/main-03 | C:/Users/user/orca/workspaces/Grid Defenders/메인03 |
| UI·전투화면 담당 | feature/ui-landscape | C:/Users/user/orca/workspaces/Grid Defenders/UI-전투화면 |

기존 작업 공간의 위치·Git 브랜치·이력은 유지한다. 실제 부모/자식 관계는 사용자 요청에 맞춰 [세계관 도메인 트리](도메인/README.md)로 재배치했다. 원본 규정과 변경 사항은 [도메인별 기준](기준/README.md)에서 찾는다. 세 메인은 동등한 역할이며 담당 메인은 작업대장의 소유자로 결정한다.

## 시작 방법

1. [규정 A](규정A.md), [메인 운영](메인운영규정.md), [프로젝트 인계](프로젝트빠른이해.md)를 읽는다.
2. 사용자는 어느 메인에서든 요청·시안 비교·부분 선택·피드백을 진행한다.
3. 메인은 필요하면 실제 시안을 만들고 선택 조합을 보여준다. **최초·수정 지시 모두 이해가 맞다는 사용자 확인 후** 담당 브랜치에 보낸다.
4. [작업대장 도구](도구/사용법.md)에서 작업번호·담당·확인 근거·차수·영수증을 연결한다.
5. 결과·검증·규정 보완안을 메인에서 확인하고 사용자 판정 후 수정 또는 통합한다.

다른 창의 대화 전체가 자동 공유되는 것은 아니다. 공유 작업대장과 최신 규정·실제 참조 파일로 맥락을 연결한다. 기존 main의 미커밋 구현은 원본 보존 상태이고, UI 담당 공간에는 복제 검증한 현재 작업 사본을 두었다. 새 UI 편집은 해당 공간에서 진행한다. 각 메인의 독립 시안은 자기 `메인작업/<main-id>/`에 저장한다.

현재 실제 제작 지시0건. '슬라임 제작'과 '시안10종'은 운영 방식의 예시이며 이번에 발송하지 않았다. 초기 채팅 준비는 [OPS-001 기록](기록/OPS-001/상태.json), 현재 도메인 계층은 [OPS-002 기록](기록/OPS-002/상태.json)을 따른다. 채팅 생성과 앱 화면의4분할 GUI 배치는 구분한다.

## 현재 도메인 분류 (OPS-002)

```text
세계관
├─ 몬스터
│  └─ 몬스터 스프라이트
└─ 캐릭터
   ├─ 캐릭터 일러스트
   ├─ 캐릭터 스프라이트
   │  └─ 영상·모션 소스
   ├─ 캐릭터 능력치
   └─ 캐릭터 스킬
      └─ 이펙트·제작도구
```

분류가 실제 작업 목록과 공유 색인에 함께 적용되어 있다. 새 세계관 관리·몬스터 스프라이트·캐릭터 능력치·캐릭터 스킬 공간은 분류·참조 준비 상태이며 이번에 새 제작 AI를 시작하지 않았다. 기존 자료의 물리적 경로와 Git 브랜치 이름은 보존한다. [정리 기록](기록/OPS-002/상태.json)과 [현재 계층 검사](기록/OPS-002/검증.json)를 확인한다.
