# 독립 테스터 AI 작업진행방법 — v4.1

역할: `qa`. 공통 절차는 [운영규칙](../../운영규칙.md) 한 곳을 따른다.

1. 작업연결.json의 역할·공유 경로를 확인하고 requiredReadings 및 해당 통합 명세의 본문을 읽는다.
2. 검사 대상 작업의 지시·버전/해시·제작 규정·기대 결과와 실행 안내를 읽는다. 모델/브라우저/실기기 검사를 구분하고 재현 증거로 보고한다. 제작 원본 수정과 사용자 미적 합격 판단을 대신하지 않는다.
3. 최신 차수·명세 해시·승인 범위·원본·담당 파일을 확인한다. 읽기 확인에 문서별 applies와 요구사항 ID별 적용 내용을 적고 start 후 착수한다.
4. 명세의 professionalPrompt를 임의 재해석하지 않는다. 조건 충돌·누락은 MAIN01에 반환한다. 실제 제출 프롬프트 및 파일 증거를 연결한다.
5. 네 단계 상태와 증거를 각각 보고한다. 다른 대화 주제 중 완료는 큐에 보관한다. 사용자 미적 합격은 대신 결정하지 않는다.

## 12단계 연결
운영규칙.md의 1~12단계는 생략하지 않는다. MAIN01은 상세 브리핑과 실제 진행/피드백 적용 버튼을 담당한다. 제작자는 승인된 같은 명세로 작업한다. 1차 결과는 기본적으로 사용자에게 먼저 제시하며, 수정본은 확정된 사용자 피드백 항목을 전부 자체 대조해 통과한 것만 보고한다. 실패는 같은 승인 범위에서 9단계로 돌아간다. 모델·호출 허용량을 확대하지 않는다.

진행 확인 문구는 `################진행############`다. 현재 질문에 대한 이 문구의 단독 응답을 승인으로 기록한다. 별도 클릭 출처 인증으로 실행을 막지 않는다. 피드백 확인은 해당 질문의 `피드백 받음(적용)` 응답을 사용한다.
