# 전체 재료함 사용법과 검증

2026-11-07. 현재 확보한 자료를 통합했다. 인터넷의 모든 무료 팩을 새로 수집했다는 뜻은 아니다.

## 정리된 내용

사용자 보관함(5182 포트)을 읽기 전용으로 확인한 결과 **798개**: 무료 재료 682개 + 공방 예제 20개 + 저장 작품 15개 + 구성 부품 81개. 동일 부품 중복을 제거하므로 저장 작품·부품 수정에 따라 개수는 달라진다. 저장 작품 원문은 조회 전후 동일했다.

무료 재료는 기본 547개, 크기·FPS 변형 포함 682개다. 이 중 3개는 풀 배경 2개와 비정형 빔 전체 시트인 **참고 소재**다. 이전 632개에 빛탄·빔 47개와 참고 3개를 추가했다. 원본 다운로드 34팩/63개는 유지했다.

19개 연출 분류: 참격·검로, 타격, 폭발·충격파, 불꽃, 물, 얼음, 전기, 레이저·빔, 투사체, 마법진·장판, 보호막·오라, 회복·강화, 상태이상, 이동·잔상, 먼지·연기, 빛·입자, 문양·기호, 소환·특수, 배경·참고. 원본 이름을 먼저 보고 팩 이름을 보조로 사용하며, 숫자로만 된 일부 효과는 밝은 배경의 프레임을 보고 별도 분류했다. 기존 ‘마법·기타’는 제거했다.

## 쓰는 순서

1. 공방 왼쪽 **전체 이펙트 재료함** 또는 `http://127.0.0.1:5182/effect-materials.html`을 연다.
2. **전체 / 무료 팩 / 공방 예제 / 내 작품 / 구성 부품**에서 출처를 고른다. 종류에서 완성 효과·구성 부품·낱개 이미지·참고 소재를 구분한다. 연출 분류와 검색을 함께 사용할 수 있다. 모바일은 **검색·분류 필터**를 펼친다.
3. 카드를 누르면 조합에 추가된다. PNG와 공방 부품을 함께 넣어 프레임 구간·시작 시각·재생 속도·색·크기·회전을 조절한다. 최대 12개 레이어, 30초/900프레임.
4. 공방 재료의 **프레임·출처 보기 → 공방 노드 부품함에 저장**을 누르면, 기존 공방의 **노드 → 부품 보관함 → 내 부품 → 현재 작품에 넣기**에서 사용한다. **레시피 JSON 저장**으로 따로 편집할 수도 있다.
5. 밝은 배경·전체 프레임·전장에서 확인하고 **게임용 PNG 시트 + 출처 ZIP**으로 출력한다. **조합 JSON 저장**은 편집 백업이다.

공방 작품을 다른 탭에서 저장하면 재료함이 갱신된다. 조합에 넣은 공방 효과는 검증된 레시피를 함께 보관한다. 원래 작품을 수정/삭제해도 기존 조합의 모습과 팔레트·노드 연결·기준점은 유지된다. 무료 PNG는 개인 원본 팩을 참조하므로 다른 컴퓨터에서 조합을 복원하려면 해당 팩도 필요하다. 원본 라이선스와 출처 ZIP은 그대로 유지한다.

평면 PNG에서 원래 불·마법진 같은 내부 레이어를 복원한 것은 아니다. 그런 파일은 프레임/구간을 골라 사용한다. 실제로 분리 가능한 공방 노드와 빛/레이저/폭발 그룹만 구성 부품으로 제공한다.

## 구현

- `materialCategories.json`은 브라우저와 Python 카탈로그 도구가 공유하는 분류 규칙이다. 숫자 이름 효과의 검토 결과도 포함한다.
- `complete-material-catalog.py`는 누락된 원본을 안전한 사각 영역으로 추출하고 전체 카탈로그를 재분류한다. 재실행해도 중복이 늘지 않는다. 전체 카탈로그 재생성 후에도 자동 실행된다.
- `recipeMaterial.ts` / `unifiedMaterials.ts`는 원본 ID가 무작위로 생성돼도 같은 레시피에 안정적인 재료 ID를 부여한다. 저장된 분류는 향후 이름 분류 규칙과 독립적으로 보존한다.
- 기존 `gd.material-composition@1`에 선택적인 `sources`를 추가했다. 사용한 레시피만 최대 12개/2MB로 보관한다. 기존 PNG 전용 조합도 그대로 읽는다.
- 절차적 렌더 결과는 원래의 투명 여백과 기준점을 유지한다. 미리보기와 전체 해상도 출력에서 같은 원본을 사용한다. 렌더 캐시는 96개/800만 픽셀, 갤러리는 화면에 보이는 카드만 8ms 작업 예산으로 순환 갱신한다.
- 모바일은 검색 필터를 접어 초기 목록 길이를 줄였다. 버튼은 48px 이상이다. 공방/갤러리 링크 명칭도 실제 범위에 맞췄다.
- 원본과 검수 이미지가 공개 소스/빌드에 섞이지 않도록 `.local/effect-materials/`와 `output/material-unified/*.{png,jpg,zip}`를 Git에서 제외한다.

## 검증 결과

- TypeScript 및 Vite 빌드 성공.
- 통합 모델 66개, 통합 UI 12개, 기존 재료함 회귀 검사 34개: **112개 검사 통과**. 원본 작품 저장소를 변경하는 UI 검사는 별도 5191 포트에서 수행했다.
- 전체 **14,611프레임** 원본/좌표/투명 여백 검사: 원본 그대로인 프레임 14,385개, 기존 검정 매트 변환 226개. ID 중복 없음, 미정리 항목 0. 기존 원본에서 셀 경계에 닿는 재료 409개는 원본 상태 그대로 표시하며, 잘린 그림을 복원했다고 주장하지 않는다.
- 혼합 연출 60프레임에서 출력 경계 접촉 없음. 밝은 회색/초록 전체 프레임 이미지 및 실제 전장 상단·중앙을 확인했다. 전장 DPR3 렌더 버퍼는 1170×1290.
- 320px·390px 화면에서 가로 넘침 없음, 표시 중 조작 요소 48px 이상. Orca DPR3 화면 캡처의 반복 타일 오류가 있어 레이아웃은 DOM 치수와 DPR1 캡처로, 전장은 실제 캔버스 픽셀을 직접 저장해 확인했다.
- 혼합 출력 ZIP에 PNG·프레임 좌표 JSON·조합 원본·사용한 팩의 크레딧이 모두 들어가는 것을 확인했다. 저장 작품 삭제 후에도 레시피를 포함한 조합이 복원된다.

검수 자료: `output/material-unified/model-checks.json`, `ui-checks.json`, `battle-check.json`, `mixed-allframes.png`, `beams-all.jpg`, `battle-Top.png`, `battle-Center.png`. 원본 전체 검사와 분류 집계는 `.local/effect-materials/frame-audit.json`, `classification-audit.json`.

## 기존 이미지 처리 경로

`art_source=existing`, `generate2dsprite`의 기존 프레임 추출·원본 보존·투명 여백·엔진 표시 검증 절차를 적용했다. 이미지 생성/API 호출은 사용하지 않았다. 비정형 빔은 `sourceRect`에 원래 좌표를 기록하고 RGBA 픽셀을 그대로 유지한다. 얽힌 영역의 원본 전체 시트도 참고 소재로 보관했다.

기능 확인 도구의 최초 `encoding.stdout` 실패는 `PYTHONUTF8=1`로 해결했다. 후속 `doctor-utf8.json`은 0 FAIL이며, 아래 환경 경고는 그대로 남아 있다. 이 경고들은 이번 Pillow 원본 추출 경로에는 필요하지 않은 생성 기능 또는 환경 안내다.

```text
[WARN   ] python.path                    other python.exe on PATH: ~/AppData/Local/Microsoft/WindowsApps/python.exe
[WARN   ] deps.scipy                     not installed; needed for faster labelling and keying (forge_core falls back to numpy)
[WARN   ] paths.cwd                      the working folder has spaces or non-ASCII characters
[WARN   ] skills.present                 ~/.codex/skills: missing generate2dmap, codeart2d
```

누락 표시된 `resvg-py` 및 이미지 생성 API 키는 이번 경로에서 사용하지 않았다. 새 게임 스킬 장착이나 공개 배포는 이 작업에 포함하지 않는다.
