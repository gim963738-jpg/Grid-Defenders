# WEB-163 · 움직이는 이펙트 갤러리

2026-11-07. 사용자는 세로로 긴 공방 목록 대신 화면 전체를 쓰는 바둑판 페이지에서 움직이는 이펙트를 한눈에 비교하고, 화려하면서 필요한 연출을 쉽게 만드는 방법을 요청했다.

## 사용법

1. 공방 왼쪽 **움직이는 갤러리 ↗**를 누른다. 주소는 `http://127.0.0.1:5182/effect-gallery.html`이다. 기존 공방 서버를 그대로 사용한다.
2. **기본 효과 / 내 작업 / 전체**에서 고르거나 이름으로 검색한다. 화면에 보이는 카드는 마우스를 올리지 않아도 함께 반복 재생된다. **일시정지 / 처음부터 / 속도 / 배경 / 카드 / 화면 가득**으로 비교 조건을 바꾼다.
3. 카드 그림이나 편집 버튼을 누른다. 기본 효과는 새 작업으로, 저장 효과는 해당 작업으로 열린다. 새 작업 진입 뒤 새로고침해도 복제본을 다시 만들지 않는다.
4. 새 연출이 필요하면 카드 오른쪽 위 책갈피로 참고를 최대 3개 고른다. **선택으로 연출 구상**에서 필요한 연출, 전체 길이, 색과 느낌을 입력하고 **요청문 복사**로 현재 대화에 전달한다. 복사 권한이 없으면 요청문을 선택해 직접 복사할 수 있다.

구상 창은 대화에 보낼 요청문을 만든다. 외부 생성 API나 자동으로 작품을 생성하는 기능은 추가하지 않았다. 참고 선택은 요청에 이름을 적는 기능이며 노드 복사 기능과는 별개다.

## 연출 제작 방법

노드 하나씩 설계하기 전에 사용처와 큰 움직임을 정한다. 예: “근접 검격, 보랏빛 번개, 0.6초, 날카롭고 묵직하게”.

- **A:** 빠르고 선명한 주동작.
- **B:** 작게 모은 뒤 크게 터지는 동작.
- **C:** 경로·회전·분열을 활용하는 동작.

같은 요청으로 움직임과 실루엣이 다른 세 시안을 새 작업에 만든 뒤 갤러리에서 비교한다. 가장 좋은 시안의 주동작을 고르고 준비 → 주동작 → 타격 → 잔상 순서로 필요한 부분만 조절한다. 가장 중요한 순간에 밝기와 크기를 집중하고 준비와 잔상은 대비가 나도록 정리한다. 피해·사거리·대상 수는 시각 연출 요청과 분리한다.

## 구현

- `게임/effect-gallery.html`, `gallery.ts`, `gallery.css`, `galleryModel.ts`: 전체 폭의 반응형 페이지. 좁은 데스크톱에서는 기본 4열, 320/390px에서는 2열. 공통 모바일 스타일과 48px 터치 영역을 사용한다.
- 기존 저장함을 읽기만 하며 손상된 저장함을 덮어쓰지 않는다. 검색·책갈피·배경·재생 설정은 작업 데이터를 변경하지 않는다.
- 동일 이름의 작업도 저장 ID로 구별한다. 공방은 `entry`/`preset` 진입을 처리하고 URL 요청을 소비해 새로고침 중복 생성을 방지한다. 누락된 작업/잘못된 기본 효과/저장 한도는 안내한다.
- 각 카드의 프레임 수/FPS를 사용하고 마지막 프레임을 0.3초 유지한 뒤 반복한다. 화면 근처 카드만 그리며 숨겨진 탭/구상 대화상자에서는 재생 시간을 멈춘다. 동작 줄이기 환경은 일시정지로 시작한다.
- PNG 문자열과 Pixi 텍스처를 만들지 않는 `renderPreviewCanvas`를 추가했다. 공방과 동일한 코어 그림 및 `padSkillFrameCanvas` 여백·발광 처리를 사용한다. 최대 320개, 한 변 최대 224px인 Canvas만 캐시한다.
- `skillVisual.ts`의 기존 여백·발광 코드를 공통 함수로 분리했으며 원본 크기·표시 크기·기준점·피해 판정은 변경하지 않았다. Vite 다중 페이지 빌드에 갤러리를 등록했다.

## 확인 결과

- 브라우저 검사 **143개 통과**: 갤러리 모델 17개(기본 효과 8종의 기존 렌더러 대비 픽셀 일치 포함), UI 15개, 공방 98개, 공통 스킬 표시 13개.
- `npm.cmd run build` 통과. 타입 검사와 프로덕션 다중 페이지 빌드 확인.
- 기본 효과 8개 모두 실제 프레임 변화 확인. PNG 변환 없는 프리뷰 단일 프레임 측정은 해당 환경에서 0.2~0.6ms였다. 전체 성능 보장은 아닌 측정값이다.
- 저장 작업 선택 시 데이터 유지, 기본 효과 새 작업 1개 생성, 진입 후 URL 소비, 새로고침 중복 생성 방지를 별도 QA 브라우저 저장함에서 확인하고 QA 저장함을 복구했다.
- 요청문 복사 성공과 권한 거부 시 수동 선택 경로, 최대 3개 참고 선택, 잘못된 저장함 보존, 검색 결과 없음, 이름 HTML 이스케이프를 확인했다.
- 320px 가로 넘침 없음, 2열, 최소 48px 컨트롤, 14px 버튼 글자. 390px/DPR3 화면과 데스크톱 화면을 확인했다. 밝은 회색 배경 전환을 검사했다.
- 사용자 원본 주소의 저장 작업 **13개**, 활성 ID 및 저장 원문 전체가 작업 전 백업과 동일함을 확인했다. 실제 사용자 창에는 기본 효과 8개가 재생 중인 갤러리를 열어 두었다.
- 효과 내용/모션을 바꾸지 않은 UI 작업이다. 이번 검증에서는 별도 전장 연출을 새로 만들지 않았으며 기존 공방 프레임과 갤러리 프레임의 픽셀 일치로 공통 렌더 분리의 영향을 확인했다.

산출물은 `output/effect-gallery/`의 `qa-report.json`, 브라우저 검사 결과, 탐색·복사·저장 보존 감사 결과 및 데스크톱/모바일/구상 창 스크린샷에 있다. 로컬 서버만 사용했으며 외부 게시나 클라우드 배포는 하지 않았다.
