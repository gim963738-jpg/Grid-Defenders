# 선 그리기 이펙트 공방 — WEB-156

2026-11-06. 사용자 요청: 노란선=돌진, 빨간선=검로, 파란선=이펙트로 그린 순서·프롬프트·설명을 함께 사용해 효과를 만들고 사용법을 제공한다. 기존 로컬 공방에 추가했다. 신규 영웅/피해/대상/쿨타임은 배정하지 않은 연출 제작 기능이다.

## 바로 사용하기

1. 기존 공방을 새로고침한 뒤 **그리기** 탭을 연다. 바로 가기: `http://127.0.0.1:5182/effect-workshop.html#drawing`.
2. **새 그림 작업**을 누르면 기존 작업과 별도로 시작한다. **돌진·검로 예제**를 누르면 노랑·빨강 동시 실행 후 파란선 끝점에서 녹색 폭발하는 예제를 만든다.
3. **돌진·이동(노랑)**을 고르고 이동할 경로를 드래그한다. 다음에 **검로(빨강)**와 **이펙트(파랑)**를 골라 원하는 선을 그린다. 화살표는 진행 방향, 숫자는 실행 단계다.
4. 기본은 그리는 순서대로 다음 단계가 된다. 앞 동작과 함께 실행하려면 **새 선 순서 → 이번 단계에 함께**로 그린다. 다시 순차 실행하려면 **다음 단계에**로 바꾼다. 이미 그린 선은 목록에서 선택해 **실행 단계**를 같은 숫자로 맞춘다.
5. 선마다 재생 시간·시작 지연·끝난 뒤 잔상을 수정한다. 같은 단계의 동작들은 함께 시작하되 각자 지연을 반영한다. 다음 단계는 앞 단계의 가장 늦은 본동작이 끝난 뒤 시작한다. 잔상은 다음 단계와 겹칠 수 있다.
6. 목록에서 선을 선택하면 설정이 열린다. **방향 반전**은 좌표 순서를 뒤집는다. **선택·점 수정** 상태에서 선의 동그란 점을 끌면 실제 경로가 바뀐다. 새로 그리려면 색상 역할 버튼을 다시 누른다. 삭제/공통 undo·redo도 지원한다.
7. 파란선은 **빛나는 선 / 빛 이동 / 끝점 폭발 / 장판·외곽 연결** 중 선택한다. 폭발 위치는 마지막 점, 크기는 그린 선의 시작~끝 거리에서 정한다. 장판은 그린 외곽을 닫아 채운다. **선이 중심으로 꼬이며 접히기**를 켜면 실제 선/외곽 좌표가 중심으로 회전·수축한다.
8. 노랑·빨강·파랑은 편집용 구분색이다. 실제 이펙트 색은 각 선의 **실제 효과색**에서 정한다. **돌진 따라가기**는 캔버스 중심(.5,.5)을 움직이는 캐릭터 위치로 취급하며 검로/효과를 함께 이동시킨다. 미설정이면 그린 위치에 고정한다.
9. 전체 설명과 선별 설명을 적고 **설명 반영**을 누른다. 예: ‘노란선으로 돌진하면서 빨간 검로로 베고, 파란선 끝에서 녹색 폭발’. 지원 단어의 색상·표현·잔상을 반영한다. 선별 표현 설명을 전체 표현 설명보다 우선한다.
10. **그림으로 생성**을 누르면 미리보기가 재생된다. 회색 인물 표식은 이동 확인용이다. **실제 전장**에서는 게임 캐릭터 이미지로 이동을 확인한다. **전체 프레임**에서 밝은 회색/초록 배경으로 모든 프레임을 확인한다.
11. **AI에 세부 요청**은 그린 좌표 전체와 설명·형식 안내를 포함한 프롬프트를 연다. 복사해서 대화에 전달하고 완전한 작업 JSON을 받아 가져올 수 있다. 작업 JSON에 그림·설명까지 저장되므로 백업한다.

화면 안 **사용법** 버튼에도 주요 절차를 제공한다. 마우스·펜·터치의 Pointer Events를 사용하며, 캔버스 안에서는 그리기, 바깥에서는 페이지 스크롤을 한다. 취소된 제스처는 저장하지 않는다. 가로/세로 동일 배율의 캔버스를 사용한다.

## 설명 반영의 범위

외부 AI/API를 자동 호출하지 않는다. 로컬에서 지원하는 표현은 녹색/초록·노랑·빨강·파랑·보라·흰색, 빛 이동/구슬, 장판/외곽/다각형, 폭발/폭팔, 연결/번개/빛나는 선, 접힘/꼬임, 잔상/유지다. 인식되지 않는 문장은 설명으로 보존하고 임의로 다른 효과를 생성하지 않는다. 모양/시간/방향은 그린 좌표와 명시적인 설정으로 결정한다. 복잡한 자연어 전체의 자동 해석·임의의 캐릭터 새 포즈 생성은 포함하지 않는다.

## 데이터·시간 계약

`gd.effect@1`에 선택 필드 `drawing`을 추가했다. 필드가 없는 기존 JSON/저장은 그대로 검증·재생한다.

- `drawing`: `version:1`, `enabled`, `showBase`, `prompt`(3000자), `strokes`(최대24개).
- 각 선: 고유 `id`, `role:'move'|'slash'|'effect'`, `points:[[x,y],…]`(2~256점, 각0~1), `step`(1~24), `duration`(.1~5초), `delay`(0~5초), `linger`(0~5초), 실제 `color`(HEX), `width`(.005~.06), `style:'trail'|'orb'|'burst'|'field'`, `followActor`, `fold`, `note`(600자).
- 같은 단계에는 캐릭터 이동선 하나만 허용한다. 단계 번호를 오름차순으로 실행하며, 번호 사이의 빈 단계는 대기 시간이 아니다. 실제 대기는 delay로 지정한다.
- 전체 길이는 잔상 포함60초 이하. 생성/그림 수정 시2~64프레임과 FPS를 전체 단계 길이에 맞춘다. 임의의 FPS/프레임 변경으로 단계를 자르는 설정은 검증에서 거절한다.
- 이동은 경로 길이를 기준으로 보간하므로 마우스 샘플이 촘촘한 구간에서 속도가 불필요하게 느려지지 않는다. 이전 단계 끝점과 다음 단계 시작점이 다르면 순간 이동할 수 있으므로 연속 이동은 시작점을 맞춘다. 동작 전/후에는 시작/끝 위치를 유지한다.
- `showBase:false`이면 기존 절차적 레이어를 보존하면서 그린 연출만 표시한다. 기존 레이어를 함께 합성할 수도 있고 그린 연출을 끄고 기존 레이어를 볼 수도 있다.

## 원본·표시·출력 계약

캐릭터 이동과 피해 판정을 분리한다. 실제 전장 미리보기는 독립 모델이며 전투 공격/피해/경제/보상을 진행하지 않는다. 기존 플레이어 저장 키를 수정하지 않는다. 전장 위치를 클릭해 기준점을 옮기면 그림 전체가 같은 좌표계로 이동한다.

신규 그림도 기존 `SkillFrameSpec → createSkillFrame → SkillFrameArt`를 사용한다. 투명 원본과 사방24px 패딩, 고정 pivot, `displaySize/contentHeight` 균일 배율을 따른다. 이름/체력 등 라벨보다 아래, 캐릭터 본체보다 위의 공용 효과 레이어에 VFX를 표시한다. 원본 경계에 닿는 그림은 출력 전에 안내하며 그림을 강제로 잘라 숨기지 않는다.

**PNG는 이펙트 그림만 담는다.** 노란 편집선/인물 표식/게임 캐릭터 자체는 PNG에 합성하지 않는다. 노란 이동은 배치 JSON의 `actorMotion`(프레임별 정규화 위치)과 `drawing` 원본 데이터로 출력한다. 캐릭터 이동과 이펙트 PNG를 게임에서 조합하는 데 사용할 수 있다. 실제 전투 스킬 연결은 후속 작업이다. 이동만 그린 작업은 빈 PNG 출력 대신 이동 정보 JSON을 받을 수 있다.
