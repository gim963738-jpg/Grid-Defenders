# OPS-001 사전 확인

작성 시점: 구현·브랜치 생성·기존 파일 수정 전에 작성했다. 사용자의 최신 요청은 새로운 작업 방식에 필요한 폴더·규정·메인 채팅 및 작업 브랜치의 실제 준비다.

## 승인된 범위

- 현재 채팅을 메인01로 유지하고, 독립적으로 요청·분석·시안 제작·지시·검수를 하는 메인02·03 작업 공간과 채팅을 만든다. 총 메인은3개다.
- 기존 UI 제작은 별도 작업 브랜치로 연결한다. 기존 main의 미커밋 코드·자산은 백업하고 보존하며, UI 브랜치에 필요한 현재 작업 사본을 전달한다.
- 기존7개 전문 작업 공간의 원래 규정과 변경 사항을 조사·보존한다. 공통 규정 A와 분야별 연결 규정, 작업대장, 요청·지시·결과·피드백·규정 갱신 양식을 작성한다.
- 메인은 시안도 직접 도출한다. 시안 선택·부분 조합 결과를 사용자에게 보여 이해가 맞다는 확인을 받은 뒤에만 제작·수정 지시를 발송한다.
- 이번 준비를 위한 역할 안내만 초기화한다. 예시 슬라임 제작·디자인10종 제작·미승인 개선 작업은 발송하지 않는다.

## 대상

작업관리/ 신규 공통 운영 폴더, AGENTS.md의 역할 연결, 기존 분야별 AGENTS.md의 보존형 연결 추가, task.md·현재 문서, Orca 메인02·03 및 UI 작업 공간·채팅·표시 이름. 기존 게임 소스를 새로 구현하거나 기존 전문 브랜치의 원본 자산·규정을 삭제·통합하지 않는다.

예정 새 Git 브랜치: coord/main-02, coord/main-03, feature/ui-landscape. 실제 생성된 이름·경로·채팅 핸들은 검증 후 작업 목록에 기록한다. 메인01의 main 브랜치는 유지한다.

## 보존 및 검증

사전 확인 결과 main은1a54b47, 원격 main은e31227b이며 main에는 기존 미커밋 변경이 있다. 커밋·푸시·리셋·스태시는 수행하지 않는다. 루트 변경 사본과 수정 대상 규정은 저장소 밖의 별도 백업에 보관한다.

완료 기준: 실제 메인3개·UI 전용 작업 공간 존재, 기존7개 분야의 경로와 기준 목록 연결, 공통 규정·양식·작업 관리 도구 사용 가능, 확인 없는 지시 준비 차단·충돌 차단 검증, UI 사본과 원본 코드 일치 확인, 실제 채팅 초기화 수신 증거 기록. 앱 화면4분할의 GUI 배치는 채팅 생성 여부와 구분해 기록한다.

검증은 JSON·문서 링크·경로·작업 관리 절차·Git 상태·Orca 생성/초기화 영수증·복제 해시로 수행한다. 게임 코드를 바꾸지 않는 준비 작업이므로 전체 전투 테스트를 불필요하게 반복하지 않는다. UI 사본의 실행 의존성이 필요한 경우 별도 확인한다.
