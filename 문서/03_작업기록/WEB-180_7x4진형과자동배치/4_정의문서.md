# WEB-180 진형 정의

상태: 구현·브라우저/모델 검증 완료, 사용자 외관 확인 전.

| 항목 | 정의 |
|---|---|
| 편집판 | 가로7×세로4, 28칸. 위쪽이 전열. 내부 cell은0~27, 화면 빈칸 번호는1~28 |
| 구역 | 1행 전열, 2~3행 중열, 4행 후열 |
| 영웅 | 자동·수동 모두 중열만 허용. 다른 병사와 교환해도 중열을 벗어날 수 없음 |
| 자동배치 | 영웅 중열 → 각 병과 선호 구역 확보 → 남은 병사 분산. 보병 전열, 궁병·마법병 후열. 각 행 중앙부터 좌우로 배치 |
| 수동 조작 | 유닛 클릭/터치 후 빈칸 클릭으로 이동, 점유 칸 클릭으로 교환, 같은 유닛 재클릭으로 선택 취소 |
| 유닛 변경 | 소환된 ID와 연결. 신규 소환은 빈칸 추가, 판매는 해당 항목 제거, 초기화는 전부 비움 |
| 편집 상태 | native dialog, 전투 일시정지·배경 스크롤 잠금. 완료/ESC/배경 클릭으로 종료, 기존 정지 여부 복원 |
| 저장 | 변경 즉시 기존 전투 체크포인트에 기록. formation 없는 v1은 복원 시 자동 배정 |
| 보스전 | 다음 보스 생성 시 적용. 기존 오른쪽 진행 화면으로 시계90° 회전. 월드좌표 x=(3-row+0.5)×56.25, y=37.5+(column+0.5)×56.25 |

↳ 쉽게 말하면: 진형창에서는 위쪽으로 전진하는 모습으로 편집하고, 실제 보스전에서는 같은 전열·중열·후열 순서를 유지한 채 오른쪽을 향한다. 웨이브에서 이미 세워 둔 위치는 바뀌지 않는다.

칸28개는 진형 선택 공간이다. 기존 전장 배치 한도20명·영웅 한도3명은 늘리지 않는다. 선호 구역이 꽉 차면 병사는 다른 빈칸에 들어가지만 영웅은 중열을 유지한다.

주요 구현: 게임/src/battleFormation.ts, formation-panel.ts/css, defense.ts, battleSave.ts, bossBattle.ts, main.ts, landscape-entry.ts, landscape-game.css. 공통 화면 규격은 [모바일UI규격](../../00_개발규칙/모바일UI규격.md)을 따른다.
