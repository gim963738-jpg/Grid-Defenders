# OPS-002 사전 확인

작성 시점: 작업 공간 생성·계층 변경·운영 원본 수정 전에 작성했다. 사용자 최신 요청은 작업 공정별 목록을 세계관 중심 도메인 계층으로 재배치하는 것이다.

## 요청 구조와 처리

```text
세계관
├─ 몬스터
│  └─ 몬스터 스프라이트
└─ 캐릭터
   ├─ 캐릭터 일러스트
   ├─ 캐릭터 스프라이트
   ├─ 캐릭터 능력치
   └─ 캐릭터 스킬
```

기존 몬스터·캐릭터·일러스트·캐릭터 스프라이트 작업 공간을 재사용한다. 없는 세계관 관리·몬스터 스프라이트·캐릭터 능력치·캐릭터 스킬 공간은 새로 만든다. 예정 Git 브랜치는 domain/world-index, domain/monster-sprites, domain/character-stats, domain/character-skills다. 실제 생성 결과를 기록한다.

기존 영상·모션 소스는 캐릭터 스프라이트 아래에, 이펙트·제작 도구는 캐릭터 스킬 아래에 보존한다. 공용 도구라는 성격은 유지하고 다른 도메인에서 참조할 수 있게 표시한다. 메인3개와 UI·아이템의 기존 연결은 유지한다.

## 대상과 보존

Orca 표시 이름·부모/자식 관계, 공유 브랜치목록·분야별 연결 규정·도메인 색인·운영 안내·관련 검사·현재 작업 목록을 수정한다. 기존 Git 브랜치 이름과 실제 파일 경로·작업 이력·미커밋 변경·기존 전문 규정은 보존한다. 새 공간은 분류·기획 연결 용도이며 원본 자료는 원래 위치를 명시해 참조한다. 기존 자료를 새 기획 값이나 합격 결과로 재판정하지 않는다.

계층은 작업 목록의 Nesting이며 Git 병합이나 모든 파일의 물리적 이동이 아니다. 전후 Orca 상태와 수정 대상 파일을 저장소 밖에 백업한다. 게임 코드·캐릭터 수치·스킬·이미지를 새로 제작하거나 변경하지 않는다. 새 제작 AI나 실제 제작 지시도 발송하지 않는다.

## 완료 기준·검증

실제 Orca 부모/자식 관계가 요청한 계층과 일치하고 순환·중복 부모가 없어야 한다. 기존 작업 공간의 경로·HEAD·Git 브랜치는 바뀌지 않아야 하며 원본 지침은 보존되어야 한다. 새 도메인 색인에서 실제 원본과 담당 작업 공간을 찾을 수 있어야 한다. 작업대장의 기존 역할 ID와 확인 절차를 유지하면서 새 역할로도 발송 준비를 할 수 있어야 한다.

검증은 공식 Orca JSON의 전후 비교, 도메인 트리·참조 경로·문서 링크 검사, 기존 절차 검사와 새 계층 검증으로 수행한다. 게임 동작을 변경하지 않으므로 전투 전체 빌드를 반복하지 않는다. 커밋·푸시·파일 삭제·미커밋 변경 초기화는 하지 않는다.
