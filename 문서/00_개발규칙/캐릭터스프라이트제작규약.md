# 캐릭터 스프라이트 제작 규약 v1.2

2026-11-05. 사용자 요청으로 저장한 공통 제작 기준. 새로운 이미지와 캐릭터에도 적용한다. 최신 사용자 지시가 우선하며 변경 이유와 버전을 기록한다. 승인 절차를 추가하지 않는다. 공격·스킬·타격은 [스킬 구현 규약](스킬구현규약.md)도 함께 적용한다.

## 1. 시각 기준과 원본

- 구성 예시: `문서/참조/캐릭터스프라이트/구성형식예시_v1.png`. 최초 첨부 이미지는 일러스트와 여러 동작을 제시하는 구성 형식만 참고한다. 캐릭터·세계관·색상·의상·무기·화풍·전신 비율의 제작 기준이나 추출용 원본으로 사용하지 않는다. 현재는 첫 초안을 새로 시작하는 단계이며 캐릭터 디자인과 공통 화풍은 아직 확정되지 않았다.
- 분위기·세계관·팔레트·신체 비율은 앞으로 만드는 첫 초안에서 정한다. 구성 예시의 장르나 색 조합을 가져와 고정하지 않는다. 공통 기준이 정해진 이후에는 새 캐릭터의 고유 디자인을 보존하면서 채도·명암·광원·픽셀 밀도를 맞춘다.
- 게임용은 디테일한 픽셀 아트다. 손으로 정리한 듯한 명확한 픽셀 군집, 계단형 윤곽, 소재별 3~5단계 명암을 사용한다. 사진 질감, 흐린 브러시, 매끈한 벡터 윤곽, 무분별한 디더링, 흐림 필터를 피한다. 어두운 의상 내부도 구분 가능하게 한다.
- 기본은 오른쪽을 향한 측면에 가까운 3/4 전신, 눈높이 카메라, 원근과 광원 고정이다. 캐릭터별 예외는 명세에 기록한다. 기본 논리 해상도에서 대기 자세의 발바닥~정수리는 약 192px로 시작하고 첫 도트 원본에 실제 높이를 확정 기록한다. 이후 그 높이와 픽셀 밀도를 기준으로 유지한다. 캔버스를 키울 때 캐릭터 자체를 확대하거나 축소하지 않는다.
- 얼굴·체형·머리 길이·장식·옷 문양·무기 길이와 두께를 캐릭터 기준표에 고정한다. 무기 길이는 픽셀 수와 키 대비 비율을 함께 기록하고, 원근에 따른 투영 변화와 실제 디자인 변경을 구분한다.
- 기준 일러스트, 첫 정리된 도트 대기 원본, 팔레트, 캐릭터 기준표를 보존한다. 이후 생성에는 같은 기준 이미지와 첫 도트 원본을 함께 참조한다. 텍스트 프롬프트만으로 화풍 일치를 보장했다고 판단하지 않는다.

## 2. 60프레임과 동작 순서

- 제작은 항목별 독립 작업으로 진행한다. `illustration` 일러스트, `idle` 대기상황, `attack` 평타모션, `walk` 걷기모션, `skill_effect_01` 스킬이펙트1, `skill_effect_02` 스킬이펙트2 등을 각각 별도 생성·수정·출력한다. 여러 항목을 한 장의 종합 시트로 합치거나 한 번에 생성하는 것을 기본 작업 방식으로 삼지 않는다. 첫 첨부 이미지의 상하 구성도 재현할 의무가 없다.
- 일러스트는 독립된 정지 이미지이며 60프레임 규칙을 적용하지 않는다. 각 모션과 개별 스킬 이펙트에 60프레임 기준을 적용한다. 스킬별 이펙트를 서로 섞지 않으며, 스킬 시전자 모션이 필요하면 `skill_motion_01`처럼 이펙트와 구별해 별도 항목으로 관리한다.
- 각 항목은 별도 폴더와 파일 접두어, 라벨, 순서표 및 메타데이터를 갖는다. 한 항목의 60프레임을 여러 페이지로 나누는 것은 허용하되, 그 페이지에 다른 동작을 끼워 넣지 않는다. 아직 요청하지 않은 항목을 현재 작업에 임의로 포함하지 않는다. 공통 캐릭터·도트 기준은 항목 간 공유한다.

- 기본 해석은 **상태 하나당 60개 시간 프레임, 60fps, 기본 1초**다. 전체 상태를 합쳐 60장으로 만들지 않는다. 동작 길이가 달라야 하면 `fps`, 각 프레임 시간, 총 재생 시간을 명세에 명시한다. 기존 게임의 공격 속도나 피해 시점을 자동 변경하지 않는다.
- 상태별로 시트를 분리한다: `idle` 대기, `walk` 걷기, `attack` 기본 공격. 피격·사망·개별 스킬은 필요할 때 같은 규칙으로 추가한다.
- 논리 번호는 상태마다 `001~060`. 왼쪽→오른쪽, 위→아래 순으로 읽고 여러 페이지에서도 번호가 이어진다. 파일명 정렬과 재생 순서가 같아야 한다.
- 대기 기본 설계: 001~015 숨 들이쉬기, 016~030 정점에서 이완, 031~045 숨 내쉬기, 046~060 기준 자세 복귀. 머리카락·옷자락은 작은 후행 움직임을 준다.
- 걷기 기본 설계: 001 왼발 접지, 008 체중 하강, 016 교차, 023 상승, 031 오른발 접지, 038 체중 하강, 046 교차, 053 상승, 060 다음 001로 연결. 제자리 보행이며 실제 이동은 엔진이 담당한다.
- 공격 기본 설계: 001~012 준비, 013~024 예비 동작, 025~032 휘두르기, 033~040 후속 동작, 041~060 회수. 이는 신규 동작의 초안이며, 타격 프레임은 캐릭터별 별도 지정한다. 피해는 지정 프레임 종료 시 확정하며 그림만 보고 추측하지 않는다.
- 반복 동작은 060→001 연결까지 검사한다. 001을 060에 단순 복사하여 멈칫거리는 구간을 만들지 않는다. 의도적인 홀드는 명세에 기록하고, 같은 그림 복제로 60장만 채우거나 흐림·크로스페이드로 중간 프레임을 대체하지 않는다.

## 3. 셀 크기·안전 여백·기준점

- **무기 끝, 머리카락, 옷자락, 몸, 잔상까지 어느 프레임에서도 잘리지 않아야 한다.** 작은 고정 칸에 맞추기 위해 신체나 무기를 줄이지 않는다. 이미 잘린 원본은 여백 추가로 복구된 것으로 취급하지 않는다.
- 먼저 60프레임 전체 동작의 최대 확장 범위를 공통 발밑 기준점 기준으로 계산한다. 좌·우·상·하 각각의 최대 범위에 안전 여백을 더해 셀 크기를 결정한다. 초기 작업 캔버스는 384×384 논리 px부터 시작하되 이는 상한이 아니다. 긴 무기·큰 공격은 가로나 세로를 필요한 만큼 확장한다.
- 안전 여백은 논리 해상도에서 사방 최소 24px 또는 셀 긴 변의 5% 중 큰 값이다. 출력 배율만큼 함께 확대한다. 불투명 픽셀은 안전 영역 안에 있어야 하며 셀 외곽 alpha는 0이어야 한다.
- 한 상태의 모든 페이지는 같은 셀 크기·픽셀 밀도·pivot을 사용한다. 상태 간 셀 크기가 달라도 동일한 캐릭터 크기와 발밑 기준점을 유지한다. 프레임별 자동 중앙 정렬과 개별 확대·축소를 금지한다.
- pivot은 기준 대기 자세에서 양발 접지점 사이의 지면 기준점이다. 각 셀에서 고정된 좌표로 기록한다. 걷기의 발 교대나 점프 때문에 pivot이 흔들리지 않게 한다. 점프의 시각 이동과 엔진 이동은 중복 적용하지 않는다.
- 기본은 잘라내지 않은 동일 크기 셀이다. 최적화로 trim할 때만 원래 셀 크기·잘린 위치·pivot을 함께 보존한다. 시각 바운드와 충돌·피해 판정은 별도다.

## 4. 페이지·라벨·산출물

- 한 상태는 기본 **5열×4행, 페이지당 20프레임, 총 3페이지**로 나눈다. p01=001~020, p02=021~040, p03=041~060. 출력 한계를 넘으면 열·행을 줄이고 페이지를 늘린다. 장수를 줄이려고 캐릭터의 디테일이나 여백을 줄이지 않는다. 실제 배치는 메타데이터에 기록한다.
- 검수용 시트 왼쪽 위의 별도 헤더에 `캐릭터 ID / 상태(한글·영문) / 방향 / 60fps / 프레임 범위 / 페이지 / 셀 크기 / 규약 버전`을 표시한다. 각 셀의 번호도 전용 공간에 표기한다. 라벨·번호는 그림과 겹치지 않는다.
- 인게임용은 투명 RGBA PNG이며 라벨·번호·테두리를 픽셀 안에 넣지 않는다. **라벨이 있는 검수용 시트와 깨끗한 인게임용 시트를 함께 납품**한다. 검수본 헤더와 번호 영역은 추출 영역에서 제외한다.
- 기본 파일명: `{id}_{state}_{direction}_p01.png`, 검수본은 `_review.png`, 개별 원본은 `{id}_{state}_{direction}_001.png`. 첫 제작의 ID는 캐릭터 이름이 없으면 `char001`, 방향은 `right`로 한다.
- PNG는 논리 해상도 1배를 기준으로 보존한다. 확대본은 정수 배율의 nearest-neighbor만 사용하고 배율을 기록한다. 각 프레임 PNG, 페이지 시트, 메타데이터 JSON, 순서표 CSV, 밝은 배경 검수본과 60fps 재생 미리보기를 함께 관리한다.
- JSON에는 `specVersion`, `characterId`, `styleReference`, `state`, `direction`, `fps`, `loop`, `frameCount`, `cellSize`, `pivot`, `characterHeight`, `exportScale`, `pages`, `frames`를 기록한다. 각 프레임은 `index`(1부터), `page`, `rect`(좌상단 원점의 x/y/w/h), `durationMs`, `contentBounds`를 포함한다. 공격은 `hitFrames`와 각 타격의 확정 시점도 별도 기록한다. 미정인 전투 값은 미정으로 남긴다.
- CSV는 `state,index,page,row,column,x,y,width,height,pivotX,pivotY,durationMs,phase` 순서로 기록한다. row/column/index는 1부터, 픽셀 좌표는 0부터다. 기본 각 프레임 시간은 정확히 1000/60ms이며 반올림 누적으로 재생 시간이 틀어지지 않게 한다.

## 5. 생성 지시 템플릿

> 이번 작업용 캐릭터 자료와 [이번 초안의 화풍 지시]에 따라 세밀한 픽셀 아트로 [캐릭터 ID]의 [상태]를 제작한다. 첫 초안에서 얼굴, 체형, 의상 문양, 장식, 무기 비율, 픽셀 밀도, 광원, 시점을 정하고 후속 프레임에서 유지한다. 공통 도트 기준이 확정된 이후에는 그 원본도 참조한다. 최초 첨부 이미지의 캐릭터와 화풍은 복제하지 않는다. 오른쪽 3/4 전신, 투명 배경. 상태당 60시간 프레임, 60fps. 이번 범위는 [001~020 등]이며 전체 동작 단계와 앞뒤 프레임에 연결한다. 공통 발밑 pivot과 같은 캐릭터 크기를 유지한다. 모든 프레임의 무기·신체·머리카락·의상·잔상을 온전히 넣고 사방 안전 여백을 확보한다. 셀이 부족하면 캔버스와 페이지를 늘린다. 흐림이나 리사이즈로 도트를 대체하지 않는다. 게임 원본에 글자를 넣지 않고, 검수본에 별도 헤더와 프레임 번호를 정확히 합성한다.

생성 결과는 초안이다. 실제 프레임 수, 픽셀 격자, 투명도, 동일 디자인, 기준점, 동작 연결을 확인하고 정리한 뒤 납품한다. 생성기가 정확한 칸·문자·순서를 지켰다고 가정하지 않는다.

## 6. 완료 기준과 변경 기록

- 001~060 누락·중복 번호와 페이지 매핑, PNG 크기·투명도, 안전 여백, 고정 pivot, 무기 비율과 신체 보존을 검사한다.
- 모든 프레임을 밝은 회색·밝은 초록 및 어두운 배경에서 확인한다. 1배 픽셀 보기와 정수 확대, 60fps 재생과 저속 재생, 반복 연결을 확인한다. 검수본과 게임용에 라벨이 섞이지 않았는지 확인한다.
- 인게임에 적용할 때 실제 전장의 중앙·가장자리, 인접 유닛, 작은 화면에서 잘림·크기·가독성을 확인한다. 문서 작성이나 이미지 생성만 한 단계에서는 인게임 검증 완료라고 기록하지 않는다.
- 최초 정리된 도트 원본이 생기면 기준표에 실제 팔레트·키·무기 길이·pivot과 파일 경로를 기록한다. 최초 첨부 이미지는 구성 형식 예시이며 첫 초안과 완성 도트 화풍은 아직 미정이다.
- v1: 사용자 요청의 넉넉한 셀, 다중 페이지 허용, 60프레임, 순서 정의, 왼쪽 위 상태 라벨, 세밀한 도트, 새 이미지에도 유지되는 화풍을 최초 문서화했다. 60프레임은 상태당 60장/60fps로 초기 해석했다.

- v1.1: 사용자 정정 반영. 최초 첨부 이미지를 구성 형식 예시로 한정했다. 예시에서 임의로 도출한 동양 판타지 분위기와 팔레트 고정을 해제하고 지금부터 첫 초안을 제작하는 단계임을 명시했다.

- v1.2: 사용자 요청에 따라 일러스트·대기·평타·걷기·개별 스킬 이펙트를 각각 독립 제작·출력하는 방식으로 명시했다. 일러스트에는 60프레임을 적용하지 않으며 항목 내부의 다중 페이지와 항목 간 분리를 구별했다.
