# SP13 캐릭터 스플래시 아트 생성 프롬프트

**캐릭터 콘셉트 → 대표 상징 → 배경 유형 → 세 층의 공간 → 인물과 배경의 상호작용 → 빛과 색** 순서로 작성한다. 배경을 고르기 전에 인물의 역할과 장면 행동을 한 문장으로 정한다.

[배경 구성 규칙과 13장 분석](SP13_배경구성규칙.md) · [입력 양식](SP13_입력양식.json) · [참조 ID·실제 파일 경로](../../../../자료/스플래시아트/SP13/참조목록.json)

현재는 제공 이미지 분석으로 만든 재사용 양식이다. 이 프롬프트의 신규 스플래시 생성 결과를 검증한 상태는 아니다. 입력 양식은 작업 설정 기록용이며 API 요청 스키마가 아니다.

## 1 먼저 채울 짧은 기획

```text
캐릭터 콘셉트: [이 인물은 어떤 역할·성격·활동·능력을 지녔는가. 확정된 내용만]
한 장면 문장: [인물]이 [자신과 관련된 무대]에서 [행동]하며 [대표 현상]을 보여준다.
대표 상징: [하나]
보조 모티프: [필요한 계열 0~2개. 개별 소품 개수를 강제하는 수치가 아님]
주 배경 유형: [T01~T08 중 하나]
선택한 참조: [SP13 이미지 1~2장과 각 역할]
인물에서 유지: [머리·얼굴·체형·의상·장비·색·좌우 구성]
```

캐릭터 설정이 비어 있으면 기존 자료를 먼저 확인한다. 의상에서 받은 인상을 공식 직업·새 스킬·동료 설정으로 확정하지 않는다. 콘셉트가 미정이면 시각적인 상징 제안과 확정 설정을 구분해 기록한다.

## 2 참조 이미지의 역할

원본 13장 전체를 한 번에 섞지 않는다. 제작 목적에 맞는 주 참조 하나와 필요할 때 보조 참조 하나를 고른다.

```text
이미지 1 = 확정된 캐릭터 디자인. 얼굴·머리·체형·의상·장비·색을 유지할 기준.
이미지 2 = 주 스플래시 구성 참조 [SP13 ID]. [구도/공간/빛/상징 연결]만 가져온다.
이미지 3 = 보조 참조 [ID 또는 없음]. [특정 형태/광원/재질]만 가져온다.
[별도 그림체 참조가 필요하면 실제 첨부 순서와 사용할 부분을 명시한다.]
```

이미지 번호는 이번 생성에 실제 첨부한 순서다. 캐릭터 디자인을 새로 만드는 경우에는 기존 GC9 규칙과 남성형·여성형 기준으로 먼저 확정한다. 스플래시 배경 참조의 인물 얼굴·의상·무기는 옮기지 않는다.

## 3 통합 스플래시 기본 프롬프트

아래 대괄호를 채우고 선택한 배경 유형 모듈을 덧붙인다. 선택하지 않은 항목은 지운다.

```text
Use case: stylized-concept
Asset type: 캐릭터 중심 판타지 게임 스플래시 아트 한 장
Primary request:
[캐릭터]의 확정된 디자인을 유지하며, [한 장면 문장]을 표현한다.
단순한 풍경 뒤에 인물을 붙이는 구성 대신 인물의 [역할/능력/활동/대표 장비]가
배경의 공간·형태·빛을 발생시키는 일관된 장면으로 만든다.

Input images:
이미지 1 = [캐릭터 디자인 기준과 유지할 요소].
이미지 2 = [SP13 ID, 가져올 배경 구성과 광원].
이미지 3 = [보조 역할, 없으면 이 줄 삭제].
배경 참조 인물의 얼굴·머리·체형·의상·무기·상징 고유 디자인을 복제하지 않는다.

Subject lock:
이름 또는 식별자: [내용]
고정된 성별별 체형과 얼굴: [내용 또는 캐릭터 디자인 기준 그대로]
머리·피부·눈·표정: [내용]
의상·문양·장식·장비 종류와 개수·착용 좌우: [내용]
잠글 기본 팔레트: [내용]
이 항목들은 환경광 때문에 다른 디자인이나 색으로 바꾸지 않는다.

Scene and concept:
주 유형: [T01~T08]
대표 상징 하나: [내용]
보조 모티프 계열: [내용 또는 없음]
장소 또는 테마 공간: [인물과 관련된 구조]
발생 원인: [손/장비/시선/행동]에서 [배경 현상]으로 이어지는 관계
실제 추가 인물: [없음 또는 요청된 인물·수]
큰 생물·석상·상징 초상: [없음 또는 콘셉트에 근거한 요청 요소와 역할]

Depth and composition:
전경 = [크기·거리·겹침을 만드는 제한된 요소]
중경 = [주인공·행동·주 장비]
후경 = [큰 무대 구조·대표 상징·대기]
주 시선 흐름 = [사선/V/열린 C·S/수직/사각 투영/확대 초상 중 적합한 구조]
인물 위치와 화면 점유 = [용도와 포즈에 맞춘 설명]
얼굴·중요한 손·주 장비 주변에는 읽을 수 있는 공간을 남긴다.
접지 또는 부유 = [발이 닿는 면·그림자 / 부유를 설명하는 흐름과 옷자락]
카메라와 원근 = [시점·거리·공간 깊이]
포즈와 시선 = [장면 행동에 맞춤. 4면도 자세를 자동 반복하지 않음]

Lighting and palette:
주 광원 = [방향·색·밝기]
보조 반사·가장자리 빛 = [필요한 경우만]
배경 기본색 = [내용]
강조색과 사용 영역 = [내용]
같은 환경광이 피부·천·금속·바닥에 일관되게 작용하게 한다.
얼굴과 주요 행동을 먼저 읽히게 하고 배후 형상·효과가 이를 가리지 않게 한다.

Style and finish:
캐릭터는 기존 GC9의 깨끗하고 가는 2D 애니메이션 선화·큰 형태 묶음·셀 명암을 유지한다.
얼굴은 C4의 간결한 눈꺼풀·코·입과 절제된 피부 표현,
금속은 C3의 분명한 면·두께·겹침·방향이 맞는 반사를 기준으로 한다.
배경도 이 인물과 어울리는 선·형태·재질 표현으로 통일한다.
큰 공간·도형·소품이 먼저 읽히고 작은 장식은 그 구조를 따른다.
가까이 봐도 얼굴·손·금속·장식 연결이 의도적으로 그려져야 한다.

Output:
화면비와 용도 = [1:1 테마형 일러스트 / 세로 카드 / 가로 키비주얼 등 하나]
바깥 처리 = [밝은 여백 비네트 / 어두운 여백 비네트 / 화면 전체 채움 / 실제 투명 비네트 중 하나]
전체 프레임에 들어갈 범위 = [인물 전신·중요 장비·연출 외곽. 의도한 전경 잘림은 별도 명시]
텍스트·로고·워터마크·UI = 없음.
한 장의 스플래시이며 추가 패널·4면도·설정표를 만들지 않는다.

Avoid:
무관한 배경 장식, 모든 예시의 상징을 합치는 것, 요청하지 않은 용·날개·마법진·추가 인물,
배경 참조 캐릭터의 디자인 복사, 흐린 얼굴·피부의 인형 광택·녹은 금속·무의미한 장식선,
전경에 가려진 얼굴·손·장비, 빛에 묻힌 실루엣, 서로 다른 원근·광원·바닥,
실사·3D 질감으로 캐릭터 그림체가 바뀌는 것, 랜덤한 가짜 수식·글자·로고.
```

## 4 배경 유형 모듈

기본 프롬프트의 `Scene and concept` 뒤에 **주 유형 한 개**를 넣는다. 보조 유형을 쓸 때는 사용할 부분을 한 문장으로 제한한다.

### T01 파편과 무장 전개

```text
주인공의 [무기/장비/문양]에서 가져온 [뾰족한 형태]를 큰 사선과 부서진 판으로 확장한다.
전경의 큰 파편, 중경의 인물, 후경의 약한 구조 윤곽으로 깊이를 구분한다.
무장과 파편의 방향이 [주 행동]으로 모이게 한다. 사슬은 설정에 있을 때만 사용한다.
```

### T02 실공간과 의식 무대

```text
[계단/문/아치/단/기둥/물가 등 콘셉트에 맞는 구조]로 인물의 장소와 등장 위치를 만든다.
인물이 서거나 떠 있는 이유, 바닥과 광원 방향, 높이 차를 분명히 한다.
후경 구조는 인물을 감싸고 얼굴 뒤의 밝기·빈 공간으로 분리한다. 모든 인물에 제단을 붙이지 않는다.
```

### T03 매체와 지식의 공간화

```text
확정된 콘셉트의 매체 [그림/책/지도/악보/도구 등]가 배경의 큰 공간 구조로 펼쳐진다.
매체 안의 [대표 모티프]가 인물의 [손/도구/시선]과 연결되어 전경 또는 후경으로 이어진다.
문자 내용이 요청되지 않았다면 작은 그래픽 표식으로 제한하고 해독 불가능한 문장·수식을 채우지 않는다.
```

### T04 속성 흐름의 프레임

```text
[속성]의 물성을 [각진 결정/유동 곡선/바람의 얇은 띠 등]로 번역한다.
주인공을 감싸는 [V/열린 원호/S]에 얼굴과 몸이 읽히는 틈을 둔다.
힘의 출발점과 이동 방향을 손·무장·시선에 연결한다. 색만 바꾼 공통 이펙트로 처리하지 않는다.
```

### T05 거대 배후 형상

```text
캐릭터 설정에 근거한 [거대 생물/석상/군상/상징 형상]을 후경에 크게 배치한다.
그 역할은 [동료/권위/두려움/상징 등 요청된 의미]이며 인물과 [손짓/빛/시선/궤도]로 연결한다.
주인공은 얼굴과 행동으로 먼저 읽히게 하고 큰 형상이 이를 가리지 않도록 대비와 디테일을 조절한다.
```

### T06 소품군과 공연 무대

```text
[활동/직업/장면]에 관련된 소품을 같은 계열로 묶고, [무대/진입로/큰 천/큰 곡선]으로 장면을 통합한다.
큰 대표 소품과 작은 반복 소품의 크기를 구분하고 색도 구역별로 묶는다.
주인공의 행동이 소품군을 사용하는 이유가 되게 한다. 작은 인물·소품을 무관하게 늘리지 않는다.
```

### T07 디지털 기하와 투영

```text
[사각/격자/직선/투영면/해체 조각] 중 정한 도형 문법으로 배경을 만든다.
인물의 손·장비에서 같은 방향과 원리로 투영물이 발생하게 하고 전경·후경에서 크기와 선명도를 달리한다.
유기적 곡선을 섞을 때는 직선과 대비시키는 역할로 제한한다. 무작위 기호·가짜 UI는 넣지 않는다.
```

### T08 확대 초상과 이중 상징

```text
실제 주인공은 한 명이다. 후경의 큰 [초상/그림자/다른 모습]은 요청된 [상징적 의미]를 나타내는 투영이다.
작은 실체와 큰 상징의 역할을 분리하고 [공통 문양/빛/무장 축]으로 연결한다.
두 얼굴이 초점을 경쟁하지 않도록 큰 초상의 대비·경계를 조절한다. 실제 인물을 두 명으로 늘리지 않는다.
```

## 5 캐릭터를 나중에 합성할 배경만 생성할 때

통합 모드와 동시에 요구하지 않는다. 아래를 기본 프롬프트의 주 요청·중경·출력 부분에 대신 사용한다.

```text
Asset type: 기존 캐릭터 스플래시용 배경 단독 이미지
Primary request: 첨부 캐릭터는 콘셉트·배치·광원 판단용이다. 최종 이미지에 캐릭터를 그리지 않는다.
배경 유형: [T01~T08]
캐릭터 예정 위치·크기·포즈: [내용]
머리·얼굴·중요 장비 예정 영역: [내용]
발이 닿을 바닥 또는 부유 중심: [내용]
카메라·지평·주 광원: [캐릭터와 맞출 내용]
전경·후경·대표 상징: [내용]
캐릭터 예정 영역은 낮은 복잡도와 대비를 유지하고, 바닥·원근·빛이 끊기지 않도록 완성한다.
인체 모양의 흰 구멍·실루엣·가이드·자리표시자를 그리지 않는다.
사람·생물·초상은 요청된 배경 요소로 명시한 경우만 허용한다.
화면비·바깥 처리·최종 합성용 여백: [내용]
```

## 6 치환 예시

아래는 구성 방식을 설명하는 기획 예시이며 신규 게임 설정이나 실제 생성 결과가 아니다. 정식 역할·능력이 없는 인물에는 먼저 시각적 제안으로 기록한다.

| 확정된 콘셉트 | 주 유형 | 한 장면으로 연결하는 방식 |
|---|---|---|
| 검보라 균열과 쌍단검이 대표인 인물 | T01, 보조로 T04의 가는 흐름 | 칼끝의 방향과 배경의 부서진 검은 판·보라색 좁은 선을 연결. 거대한 용·새 날개·새 무기는 추가하지 않음 |
| 창작과 그림이 대표인 인물 | T03 | 펼친 매체의 면이 공간을 만들고, 그 안의 대표 모티프 하나가 손·도구를 따라 전경으로 나옴 |
| 방패와 수호 문양이 대표인 인물 | T02 | 방패 문양의 큰 리듬을 문·기둥·빛의 틈에 반복하고, 발과 무대 접점을 분명히 함. 공식 종교·직업·새 능력은 임의 확정하지 않음 |

## 7 생성 후 수정 문구

```text
캐릭터 디자인·얼굴·체형·의상·장비 개수와 좌우는 유지한다.
현재 가장 큰 문제인 [문제]만 수정한다.
배경의 [대비/배치/광원/원근/상징 연결]을 [구체적인 방향]으로 바꾸고 나머지 구도는 유지한다.
새 소품·인물·능력·문양을 추가하지 않는다.
```

실제 생성에서는 한 장의 스플래시당 별도 호출을 사용하고, 사용한 원본 ID·이미지 순서·최종 프롬프트·출력 파일을 함께 저장한다. 출력 해상도·알파는 실제 반환 파일에서 확인하며 요청값을 그대로 완료 수치로 기록하지 않는다.
