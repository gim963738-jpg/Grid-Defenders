# 발로르 차수3 재반려 원인 분석 — 2026-11-10

## 사용자 판정과 범위
사용자 원문: “발로르 이번엔 삐쩍마른 캐릭터가되었어 얼굴은 부어서 팅팅분얼굴이고 매치가 전혀 안된다 완전 틀렸어 발로르 피드백 얼굴이너무큼 몸은 말라버렸음 무기는 검인데 꺾여버렸고 기껏 괜찮은 표본 만들어서 비슷하게 만들라했는데 자꾸 이상한 결과물이 나온다 이유분석”.
차수3 발로르3종은 사용자 반려. 분석 요청이며 새 제작/수정/리깅/게임적용/커밋·푸시 승인이 아니다. 금발 결과의 별도 합격까지 추정하지 않는다.

## 직접 확인한 근거
생성 출력의 balor-front.png/balor-right-035.png를 원본 배율에서 다시 열었다. generation-records.json 호출2/3의 실제 request.prompt, 제작기준.md·검수.md와 main01의 차수3 전문지시/두께반려기준을 대조했다. 원본/참조/비교 PNG는 변경하지 않았다.

1. **수정 목표를 폭 감소에 치우치게 설정했다.** main01은 좌우 두께를 더 줄이라는 지시를 반복했고, 생성 프롬프트는 SLIM COMPACT, narrow clavicle/chest, tapered slim waist, slim upper arms와 ‘armor shoulder width around the width of the head/hair group’까지 구체화했다. 마지막 머리폭 수준의 어깨 지시는 사용자가 정한 치수가 아니다. 표본의 전체 균형 재현보다 폭 축소가 앞섰다.
2. **머리·얼굴과 몸의 결합 비율을 검수하지 못했다.** 같은 프롬프트에는 LARGE actual SD skull/face, Large actual head, don't shrink head가 함께 있었다. 몸통과 팔을 줄이는 동안 얼굴은 크게 유지하도록 서로 다른 방향의 조건을 건 셈이다. 실제 결과는 좁은 흉곽·상완/하체와 넓은 얼굴의 불균형으로 읽힌다. 얼굴 표정에도 calm slight smile를 새로 강조했으며 승인 표본의 얼굴 형태·볼/턱/눈 위치를 일치 검증하지 않았다. 이것이 사용자가 지적한 얼굴 인상에 영향을 주었다는 것은 프롬프트·결과를 대조한 분석이며 모델 내부 인과를 계측한 것은 아니다.
3. **잘못된 후보를 후속 마스터로 고정했다.** 호출2의 decision은 ‘Slim body passed internal same-height front-family inspection’이고, 호출3 장비 수정 지시는 ‘Keep the successful SLIM narrow shoulders/chest/upper arms ... EXACTLY’였다. 이 단계에서 몸을 성공으로 간주하고 고정한 것이 근거에 남아 있다. 이후35/90도는 이 정면을 sole authority로 삼아 오류를 전파했다.
4. **검을 독립된 강체 구조로 충분히 검증하지 않았다.** 프롬프트에 straight blade/don't bend axis가 있어도 결과를 보장하지 않는다. 내부 수정은 검신을 약20% 연장하라는 전체 이미지 생성 요청이었고, 검수는 손→그립→가드→날의 연결·색·장식 중심이었다. 손잡이 중심축과 칼날 중심축의 연속성/직선성은 별도 판정 근거가 없다. 사용자의 꺾인 검 지적을 단순 투영·미세차이로 면책할 수 없다.
5. **기술 기록을 디자인 판정과 혼동했다.** ACK/start/파일바이트 보존/같은 표시 높이는 공정·기술 확인이다. 어깨폭이35.5→27.0으로 줄었다는 관찰도 ‘원래 표본처럼 자연스러운 기사인가’의 답이 아니다. main01은 전달 전 비교판을 열었지만 여전히 체형·얼굴·무기 결함을 걸러내지 못했다. 이번 실패는 생성 변동성만의 문제가 아니라 메인 지시·내부 후보 선정·최종 시각 검수의 실패다.

## 추가 제작 전 제안 (아직 실행하지 않음)
- 현재 반려 발로르를 체형/얼굴의 후속 마스터로 쓰지 않는다. 실패 결과는 보존한다.
- 공통 표본의 정면1장과 같은 자세/같은 표시 키로 비교하며 실제 두상(모발과 구분), 얼굴 볼·턱, 어깨·흉곽·골반·팔·다리의 결합 비율을 먼저 고정한다. 단순 ‘가늘게/크게’ 반복 지시나 임의 어깨폭=머리폭 규칙을 추가하지 않는다.
- 이 정면의 전체 균형이 확인되기 전에 각도3종으로 확장하지 않는다. 실패 범위가 여러 장으로 증식하는 것을 막는 제안이며 아직 새 사용자 승인이나 제작 명령은 아니다.
