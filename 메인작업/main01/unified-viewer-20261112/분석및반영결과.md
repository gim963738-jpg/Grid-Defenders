# 통합 결과물 뷰어 반영 결과

공통 진입점은 `/dev-previews/viewer/index.html`이다. 현재 오른쪽 결과물 탭에 발로르 Sunburst 13모션 묶음을 비교 모드로 연결하고 실제 ready 상태를 확인했다. 기존 최신 결과 페이지 3개도 이 진입점으로 연결한다. 25개 기존 자료 묶음, 원본 이미지 212개, 기록된 시트 39개를 목록으로 연결했다. 과거 개별 페이지 전체를 삭제하거나 기존 전문 공방의 편집 코드를 바꾼 것은 아니다.

## 웹 사례 분석 — 확인일 2026-11-12

|공식 자료|확인한 방식|이번 적용|
|---|---|---|
|[PureRef Navigation](https://www.pureref.com/handbook/navigation/)|이미지 중심 화면, 확대와 이동, 필요한 보조 조작만 노출|중앙 캔버스·상단 확대·접을 수 있는 보기 조절|
|[Aseprite Timeline](https://aseprite.org/docs/timeline/)|프레임을 모은 타임라인과 선택 범위|하단 프레임 목록, 번호·범위·순서를 지정한 재생|
|[Photopea Adjustments and Filters](https://www.photopea.com/learn/adjustments-filters)|원본과 분리해 조절·해제 가능한 필터|보기 전용 필터, 원복 및 원본 다운로드|

## 6개 요구사항과 구현

1. 확대/축소: 5~800%, 맞춤·1:1, 캔버스 이동과 단축키. 원본 픽셀 크기와 현재 비율을 표시한다.
2. 디자인 검토: 샤픈·안티앨리어싱·러프·블러·스케치, 강도, 해상도 및 실제 JPEG 압축 품질 시뮬레이션. 이미지 내용의 AI 재생성이나 손실 디테일 복원이 아니다. 같은 보기 설정을 기준에도 적용하거나 기준을 원래 표시로 둘 수 있다.
3. 시트: 기록된 격자/프레임 영역을 사용한다. 2,3 또는 1-5,8 같은 순서를 지정하고 FPS·반복·이전/다음을 조절한다. 시트/프레임 보기에서 같은 확대와 필터를 사용한다. 직접 불러온 시트도 칸·프레임 수·여백을 지정할 수 있다.
4. 비교/수집: referenceId가 있으면 기준/결과 나란히 보기, 없으면 시안 모음. 사용자가 비교 대상을 고를 수도 있다. 작업 기준과 사용자 승인 기준 표기를 혼동하지 않는다.
5. 설명 분리: 뷰어에는 이름·조작·수치·필요한 오류 표시만 둔다. AI 설명과 평가는 채팅에서 전달한다. 새 시각 결과의 기본 출력은 공통 뷰어 주소이며 개별 이미지 첨부를 사용하지 않는다.
6. 공통 UI: 상단 모음/보기/확대, 왼쪽 자료 목록, 중앙 이미지, 접이식 보기 조절, 하단 프레임 타임라인으로 통일했다. 좁은 창에서는 필터를 열고 닫을 수 있다.

## 실제 검증

- 브라우저 24개 기능 검사 통과, 런타임 오류 0건. 원본이 있는 비교 기본값과 최초 모음 기본값, 확대 실제 크기, 2·3 프레임 전용 재생, 필터 픽셀 변화, PNG 내보내기, 해상도 열화, 잘못된 프레임 입력, 직접 이미지 불러오기와 격자 자르기, 780px/390px 화면을 확인했다.
- 자료 이미지 212개 HTTP 로드 및 파일 해시 대조 통과. 필터와 조작 후 원본 바이트를 그대로 보존했다.
- 워크플로우 검사 71개, 등록 도구 검사 3개 통과. 시각 결과는 공통 뷰어 연결과 실제 파일을 갖춰야 제시할 수 있다. 최초 제시와 사용자 최종 합격은 별개다.
- 타입 검사와 프로덕션 빌드 통과(2.79초). 빌드에 복사된 뷰어 정적 파일도 원본과 바이트가 같다. PowerShell의 npm.ps1 실행 제한은 npm.cmd로 실행해 해결했으며 시스템 실행 정책을 변경하지 않았다.
- 실제 오른쪽 기존 결과물 탭을 공통 뷰어로 연결하고 ready=true를 확인했다. 새 분할창이나 이미지 탭을 추가하지 않았다.

근거: validation.json, browser-check.json, right-pane-navigation.json, right-pane-state-verified.json, source-images.json. 브라우저 확인 과정의 CLI 인용 오류와 최초 디렉터리 URL 탐색 오류는 정식 index.html 및 올바른 인용으로 수정했다. 과거 결과물 자체의 작화·모션 품질이나 사용자의 최종 미적 합격을 이번 검증으로 대신하지 않는다.

## 이후 결과물 등록

작업 지시의 current.outputKind와 viewer(entry,collection,catalogFile)를 정하고 `게임/scripts/register-viewer-result.py --manifest <등록 JSON>`으로 파일을 등록한다. 기준과 결과를 같은 모음에 넣고 시트 메타데이터를 함께 전달한다. 공통 목록 갱신은 기존 등록 작업을 보존한다. 원본은 해시가 같은 사본으로 연결하며 제작·수정·합격 상태를 임의로 바꾸지 않는다.

새 이미지 생성/API 호출이나 Git 커밋·푸시는 수행하지 않았다. 변경 전 운영 지침·진입점 복구 목록은 before-manifest.json이며, 실제 사용자 요청의 통합 명세는 통합작업명세.json이다. 프로젝트 운영 지침과 도구를 바꾼 것이며 앱 플랫폼 전체의 시스템 메시지를 수정한 것은 아니다.
