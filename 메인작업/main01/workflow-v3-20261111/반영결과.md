프로젝트 운영 지침과 로컬 실행 도구를 개편했다. 플랫폼의 시스템 프롬프트 자체를 변경한 것은 아니다.

검증: 워크플로우·도메인·조직 검사 50개 통과. 현재 15개 역할의 경로·브랜치·HEAD 보존, 실제 부모 관계와 필독 연결, 백업 161개, 과거 지시 파일 참조 214개 해시 대조 통과. 검사 결과는 `tests.txt`, `validation.json`이다.

14개 담당의 동일 공통 필독 묶음 합계는 457,207자 → 100,442자로 78.03% 감소했다. 새 작업 명세와 작품별 추가 자료는 이 비교에서 제외했다. 내용 자체를 무리하게 요약하지 않고 중복 운영 문서와 관련 없는 맥락 전달을 줄였다.

현재 제한을 해결하려면 Orca의 실제 사용자 선택 이벤트를 제공하는 공식 인터페이스가 필요하다. 이벤트는 질문 ID·사용자 출처·클릭/자유 입력 구분을 보증해야 하며 명세 차수·해시와 연결해 검사해야 한다. 그 연결 전에는 문자 답변이나 AI가 만든 확인 파일로 대체하지 않는다.

열린 담당 AI가 모두 새 규정을 읽었다고 보고하지 않는다. 파일 연결은 갱신했으며 다음 작업의 읽기 확인/start에서 실제 적용을 확인한다. 이번 개편으로 새 제작을 하달하거나 이미지 API를 호출하거나 Git 커밋·푸시하지 않았다.

복구: `before-manifest.json`의 원래 경로·사본·SHA-256으로 변경 전 자료를 찾는다. 이후 사용자 작업 위에 일괄 복원하지 말고 대상 파일별로 비교한다. 실제 노드 부모 변경 전후와 영수증은 `orca-worktrees-before/after.json`, `monster-parent-receipt.json`, `character-parent-receipt.json`이다.
