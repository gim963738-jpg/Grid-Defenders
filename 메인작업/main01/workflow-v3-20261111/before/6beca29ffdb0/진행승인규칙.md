# 명시적 진행 전까지 대기 — 사용자 확정 기본값 / 2026-11-09

사용자 원문: 정해놓자 내가 "진행"이라고 하기전까진 대기인걸로 02 03한테도 확실하게 이야기해놔 이거 기본값이야

메인01·02·03과 하위 제작 담당에 적용한다. 조건 추가나 구체적인 제작 요청 자체를 진행 승인으로 추론하던 이전 해석보다 이 최신 지시가 우선한다.

1. 신규 제작·수정·적용은 사용자가 해당 범위에 명시적으로 ‘진행’이라고 지시하기 전까지 대기한다. 요청 분석·조건 정리·지시문 초안 작성은 가능하지만 실제 이미지 생성/API 호출/게임 코드 수정/제작 하달은 시작하지 않는다.
2. 조건 추가·피드백·질문·개수 변경·의견·예시·‘만들어봐/뽑아와/수정해’라는 최초 요청만으로 자동 착수하지 않는다. 무엇을 진행할지 먼저 정리한다.
3. 실제 실행 지시인 ‘진행’, ‘진행해’, ‘그대로 진행해’와 사용자가 제출한 ‘이 내용으로 진행’ 선택은 승인으로 기록한다. 인용/질문 속의 단어, 버튼의 사전 선택, 침묵/시간경과/다른 채팅 이동은 승인이 아니다.
4. 실제 승인 원문·작업번호·차수·확정 범위를 기록한다. 새 범위나 별도 수정 제작에는 다시 진행 승인이 필요하다. 이미 승인된 동일 범위의 내부 구현·검수·지시된 적용 단계마다 같은 승인을 반복 요구하지 않는다.
5. 대기 작업은 ‘확인 대기 — 작업명’으로 표시하고 네이티브 선택 질문을 사용한다. 조건을 정리하는 도중 제작자에게 먼저 발송하지 않는다. 발송 뒤 받은 승인을 과거 시점의 승인으로 소급하지 않는다.
6. 팀장·하위 담당에도 동일한 승인 근거와 범위를 전달한다. 다른 메인의 승인을 대신 만들지 않는다. 이미 승인된 작업은 새 공지만으로 임의 중단·복제하지 않고 그 범위만 이어간다.

현재 20스타일×두 모델40장 작업은 사용자가 이 규칙 직전 ‘아니 그대로 진행해’라고 명시했으므로 계속한다. 앞서 조건 추가를 승인으로 오해해 발송했던 사실은 이 후속 승인을 과거 승인으로 꾸며 지우지 않는다.
