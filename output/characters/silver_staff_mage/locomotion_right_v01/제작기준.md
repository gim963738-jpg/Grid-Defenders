# 은발 지팡이 마법사 · 오른쪽 걷기/달리기 초안

2026-11-07. 사용자가 요청한 “금발 전사 걷기 정도의 품질로 마법사 걷기·달리기를 만들어 보기”를 실제 자산으로 제작했다. 캐릭터디자인2의 기존 은발·날개 지팡이 SD 원화를 정체성 기준으로 사용했다. 이 이름은 파일 식별용이며 정식 직업·세계관 설정을 추가하지 않는다.

[원본 해상도 비교 재생](preview.html) · [걷기 번호 시트](walk/review-light-numbered.png) · [달리기 번호 시트](run/review-light-numbered.png)

## 결과

| 동작 | 그림 수 | 한 주기 | 시트 / 개별 프레임 |
|---|---:|---:|---|
| 오른쪽 걷기 | 30 | 1000ms | 1536×1280 / 256×256 |
| 오른쪽 달리기 | 30 | 750ms | 1536×1280 / 256×256 |

두 시트 모두 실제 투명 RGBA PNG이며 6열×5행이다. **01→02→…→30→01**, 왼쪽부터 오른쪽으로 읽고 다음 줄로 넘어간다. 프레임 수를 맞추기 위한 반복 복사나 광학 흐름 보간은 사용하지 않았다. 최종 PNG의 서로 다른 해시 30개는 파일 구별 근거이며 동작 품질 판정 근거로 쓰지 않는다.

walk/, run/ 안에 투명 시트, 개별 PNG 30장, 무한 반복 APNG, 좌표 JSON, sequence.json, 밝은/어두운 번호 시트가 있다. 시트의 표시 기준점은 (128,228)이며 피해 판정·충돌 영역과 분리한다. 실제 게임의 이동 속도와 발 접지는 아직 연결하지 않았다.

## 제작 경로와 재현 정보

내장 image_gen을 8회 사용했다. Grok 영상·API 호출은 이번 작업에서 하지 않았다. Agent Sprite Forge의 정체성 참조·동작 계획·고정 캔버스·검수 원칙을 적용한 이미지 기반 시험 제작이며, ASF의 영상 생성 경로를 완료했다고 기록하지 않는다.

- 달리기 구간별 [A](takes_v02/run/a.prompt.txt), [B](takes_v02/run/b.prompt.txt), [C](takes_v02/run/c.prompt.txt), [D](takes_v02/run/d.prompt.txt), [연결 시도 E](takes_v02/run/e-loop-bridge.prompt.txt), [앞발 보정 F](takes_v02/run/f-boot-correction.prompt.txt).

- [캐릭터 고정 기준](character-profile.json), [동작 가이드](guides/motion-contract.json), [최종 원본 대응표](run-source-map.json)를 보존한다.

걷기 첫 시트는 채택했다. 첫 달리기 30장 시트는 발의 단계와 반복 연결이 고르지 않아 최종 자산에서 제외했다. 이후 8장씩 나눠 생성한 A1~8 → B2~8 → C2~8 → D1~5 → F6~8을 최종 30장으로 연결했다. B1/C1은 앞 구간과 겹치는 연결 확인용이라 사용하지 않는다. E는 착지 연결을 만들었지만 몸 크기와 발 위치가 달라 채택하지 않았다. F 중 마지막 3장만 사용해 원래 D의 다른 프레임을 유지했다.

원본 A~D/F는 1774×887로, 원본 셀 너비가 443.5px다. 전체 시트를 동일하게 916×458로 최근접 축소한 뒤 229px 셀을 자른다. 각 셀에 왼쪽·위 13px, 오른쪽·아래 14px 여백을 넣어 256×256로 포장한다. 걷기는 원본 1374×1145의 229px 셀을 축소 없이 같은 방식으로 포장했다. 프레임마다 몸 크기에 맞춰 잘라내거나 공중 동작의 최하단을 바닥에 정렬하지 않는다.

## 검수 결과와 현재 한계

- 밝은 배경과 어두운 배경에서 전체 프레임과 확대 하체를 확인했다. 지팡이/머리/발의 셀 경계 잘림이 없다.
- 달리기의 지지→다리 회수→공중→다음 착지 흐름을 구간으로 나눴다. 마지막 구간의 발 최하단 차이는 보정 전 약 6px에서 약 2px로 줄었다. 30→01 연결의 작은 높이 차이가 완전히 없어졌다고 주장하지 않는다.
- 머리카락·로브의 변형은 프레임 안에 포함되어 있다. 금테 무늬와 머리카락 선의 작은 변화, 신발 겹침의 가독성은 추가 검토 대상이다.
- 원본 알파는 정규화된 시트 분리 후 그대로 보존한다. System.Drawing의 알파 사전 곱셈 반올림 때문에 개별 PNG와 재포장 시트 RGB에 최대 1/255 차이가 있으며 알파 차이는 0이다.
- asset-verification.json과 browser-verification.json: PNG/시트 대응, 실제 APNG 30장·1000/750ms·무한 반복, 프레임 선택, 반복 켜기/끄기, 속도, 100~400% 확대, 휠, 드래그, 핀치, 320/390px 화면과 48px 조작 영역을 검증했다.

이 결과는 **사용자가 전체 느낌을 판단할 수 있는 첫 실물 초안**이다. 다른 모든 캐릭터에서 같은 품질이 자동 보장되는 완성 템플릿이나 공용 뼈대를 구현한 상태는 아니다. 동적 바람, 표정/피격 상태, 부위 레이어 분리, 게임 전장 통합은 이번 걷기·달리기 파일과 별도 작업이다.

채팅 표시본은 밝은 배경에 합성한 256px WebP를 사용해 원본 해상도를 유지하면서 파일 크기를 줄인다. PNG 자산의 투명도는 유지한다. preview.html은 원본 PNG와 밝은/어두운/격자 배경을 모두 지원한다.

## 다시 포장

1. powershell.exe -NoProfile -ExecutionPolicy Bypass -File assemble-run-v02.ps1
2. powershell.exe -NoProfile -ExecutionPolicy Bypass -File package-sprites.ps1
3. node encode-assets.mjs
4. Forge 가상 환경 Python으로 verify-assets.py, Node로 verify-preview.mjs.

기존 금발 전사, 캐릭터디자인2 원본, 게임 코드는 변경하지 않았다. 로컬 저장이며 커밋·푸시와 사용자 최종 확인은 아직 하지 않았다.
